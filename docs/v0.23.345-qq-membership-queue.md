# v0.23.345 · QQ 会员歌曲与 ID 队列

用户已有会员，却出现要求开通会员、歌曲只有六十秒的情况。Windows 同一客户端、
同一已登录账号、同一首《野花》（102179064／红星20号）完成了对照：旧的完整
公开目录资料经 ParseXMLFile 投递，时长为约六十秒；仅发送歌曲 ID，QQ 返回约
二百一十一秒。再发送旧资料又恢复六十秒，不是仅凭截图推断用户没有会员。
删除 pay_status 一个字段仍为试听，删除更多资料则不能播放，尚未定位到单一字段。

改用 [QQ 官方网页源码](https://y.qq.com/ryqq/js/common.chunk.ad5e47b12e2ca2168529.js?max_age=2592000)
的多首 ID 格式：一个 playsong 命令，ID 和类型各以竖线分隔。适配已有客户端的
/playbysongid 入口并实测；不是三十个独立单曲命令。公开元数据继续用于本地
版本、版权和完整性校验，但不把游客试听、付费状态或媒体资料发送给 QQ。
账号权益、歌曲资料和媒体地址由客户端自己取得，不读取凭据、不伪造权益值。

Windows 在就绪检查、元数据校验完成后、投递 ID 队列前确认顺序播放，避免原有
随机模式影响首曲。原模式按现有规则在暂停时恢复；未就绪不改模式。首次仍投递
完整三十首，手动选中某位置时投递该位置至轮末的剩余 ID，六毛保留完整歌单和
实际位置。普通曲终由 QQ 接续，最后一首结束后沿用缓存候选池生成新一轮。
十五热门加十五全曲库、轮内去重、排除现场及明确无版权、保留会员曲均不改变。

验证：ID 两首队列《野花》约211秒，下一首《隔壁阿丑》约321秒。生产入口随机
三十首，十五热门、二十六会员，起播《恍惚》约270秒，定位至第77秒仍正常播放。
另一轮选择第29首，定位曲尾后《风起时，想你》自然到《她们》，队尾生成第二轮
三十首并播放《不如怀念》（约281秒）。这是曲尾定位及换轮验证，不是三十首
全部自然播完，也不证明所有账号、地区和歌曲都必然可用。

一次试验的最小资料队列进入 stopped，旧测试守卫只认可 paused 而关闭了 QQ。
这是本次 QA 工具的误处理，不能作为此前用户账号掉线的解释。守卫现认可已停止，
默认只请求暂停；关闭客户端必须显式选择，不再因未确认状态自动关闭。普通重新
打开 QQ 后未出现登录／验证提示；没有操作认证窗口。最终结合独立媒体状态及
音量计核对停播，不保留运行中的播放试验进程。
