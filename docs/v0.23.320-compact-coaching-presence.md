# 紧凑纪律提示与运行状态

## 根因与改动

`DesktopCoachingSurface(compact=True)` 曾沿用训导卡的 8×6 外边距、米黄色外框，再嵌套青绿色动作按钮；固定 215 宽、独立字号造成两层底框，明显高于旁边计时牌。

`controls.paint_pill_surface` 供计时牌和纪律小牌共用圆角绘制。小牌移除外边距、实色矩形底框，11px 深色文字、1px 蓝灰边框；宽度按内容计算，上限 285 逻辑像素，超长保留 tooltip。`PetWindow._refresh_desktop_coaching` 在定位前同步计时牌高度，间距仍为 6px。已可见时不重复调用原生显示入口。业务结案条件、点击详情、全屏和 no-activate 规则保持原流程。

## 在线与活动

- `PetWindow._build_local_liveness_presence`：应用活着且登录 -> presence online；当前有效本地专注区间 -> activity focus；其余 -> rest，包括未开始与结束本轮。
- `SocialHubDialog` 的本人卡片同样映射，使用本地状态，不从远端读回确认自己在线。
- `SocialHeartbeatWorker` 为应用进程所有，15 秒一次。隐藏到托盘、失焦、最小化不停止；页面不注册心跳。负载为 presence/activity、会话起点证明、设备序号、必要的输入证明，不含累计统计、计划或互动历史。
- 普通退出：停止周期调度 -> 排一次 offline -> 若正在发送 online，则同一非 daemon 线程完成它后顺序发送 offline -> Qt 异步等线程完成才销毁。重复 stop 不重复发送或清除终结写入。网络失败仍保留 TTL 兜底。
- TTL 120 秒；在线、休息、工作都先受 TTL 约束。多设备账户只要其他设备仍新鲜在线，退出一台不使全账号离线。其他搭子在下一次既有列表刷新时看到更新，没有新增高频查询。

## 服务端

既有 `supabase/presence_lifecycle.sql` 函数可重放部署，无新增表、列或全量历史更新。此前展示 focus 取决于通过键鼠输入证明的 working/session_active；阅读、输入探针缺失时可能显示 idle。设备 activity 改为由明确的客户端学习活动驱动，展示批量聚合同一 activity；键鼠证明、隔离会话与奖励 working 字段继续接受原 v2 校验。只有具备会话 ID、起点且明确正在专注的载荷可宣布 focus。旧 idle 客户端兼容在线展示。

权限仍 auth.uid、锁定 search_path；展示 helper 不向客户端开放；隐私、设备序号和 TTL 约束不变。只更新函数，不重置或补写任何专注事实。

## 验证

Qt 回归覆盖同高、内容宽度、圆角外透明、去掉嵌套底色、刷新不重显、点击详情、不抢焦点门禁、全屏抑制、后台心跳和退出排队。在真实服务端以随机 synthetic 账号执行并 rollback：focus/rest/idle、输入证明与活动分离、阅读超过 10 分钟仍 focus、TTL、退出、另一设备保活、序号防倒灌、隐私和匿名拒绝；重复部署验证一致。

自动化渲染和测试不替代实机 macOS/游戏焦点验收；发布流水线需通过 Windows 与两种 macOS 构建和既有服务端门禁。
