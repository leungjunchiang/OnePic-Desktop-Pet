# v0.23.339 · QQ 冷启动先等待登录恢复

用户报告 QQ 未启动时点击随机会出现账号未登录或正在登录。本机检查旧流程后，
主窗口确实显示“点击登录”。生产代码没有退出账号或修改凭据的命令，但之前
直接使用后台与播放参数冷启动 QQ，并未检查登录恢复；不能仅凭访客也可播放的
歌曲判定账号状态正常。本次处理这一已确定的时序问题，不推测账号失效的全部原因。

Windows 冷启动现在只执行普通 QQMusic.exe，一次启动，不携带 /background、
歌单、歌曲、模式、账号或登录参数；工作目录为程序所在目录，显示采用标准启动
提示。已运行时优先复用唯一实际程序路径，不再用过期设置拉起另一 QQ 版本。
无法确认已有进程路径或出现多个版本时明确停止；不结束它们或强行重新登录。

独立限时 UIA 辅助进程只读取固定登录／验证标记、搜索框类型和前后曲按钮，不返回
账号名、搜索内容或完整界面。冷启动等待至多二十五秒，稳定读到就绪状态才继续。
正在登录时等待 QQ 自己完成；明确未登录、需要验证或超时则保留六毛三十首歌单，
不发送播放、暂停、模式恢复或重复启动。用户在 QQ 手动完成登录后再次点击随机。
没有自动操作登录窗口、读取凭据或改动自动登录设置。

歌曲与原生队列投递前还会重新确认同路径 QQ 仍运行，避免已关闭客户端被播放命令
重新冷启动；模式投递也不带后台自启动参数。未就绪有独立失败码，自动换轮和直接
点歌同样停止本机续播，不把“尚未发命令”当成播放失败而再发清理命令。
检查后到原生命令投递之间仍有短暂客户端退出竞态，不承诺所有 QQ 版本或状态均可用。

Mac 在搜索之前等待公开界面就绪，遇到明确登录或验证标记不输入歌名、不点击播放。
已有 QQ 不重新启动，冷启动沿用隐藏且不激活的 Cocoa 配置。Mac QQ 在线功能仍为
实验适配，没有本次已登录真机播放与换轮证据；SDK、完整回归、冻结启动和双架构
DMG 构建分别验证，不能代替 QQ 在线验收。DMG 未经 Developer ID 签名或公证。

Windows 验收记录：旧未登录界面下，生产管理器生成并保存三十首，返回未就绪，
潜在客户端修改动作计数为零，运行版本未改变。用户手动登录后，随机播放、手动
下一首及 QA 定位到最后四秒后的原生曲终续播通过，展开窗口保持显示。
QQ 自身会将已最小化的窗口展开；六毛没有为此再强制最小化已有窗口。

随后正常退出 QQ 客户端一次，由生产冷启动流程普通打开；再次读到就绪状态，
随机生成三十首并实际播放《歌声与微笑 (Live)》，没有再次出现登录提示。
新 QQ 主进程使用普通启动命令，而非后台加歌单参数启动；确认后初次后台收起成功。
各段使用三十秒守卫，结束暂停。此验收未读取账户身份，不等于验证任意设备的
登录资料长期有效，也未覆盖客户端自身的过期、网络或安全验证问题。
