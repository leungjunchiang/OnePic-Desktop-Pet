# v0.23.315 主动快捷入口与原生退出审计

## 日志能证明什么

用户运行日志显示：11:30 下载更新并进入退出，连续两次记录等待 Qt worker；11:30:27 新进程恢复账号，随后正常完成多个 dashboard 请求，持续到 12:18。日志没有快捷入口被拦的原因，也没有 Qt 原生 fatal 的具体信息或崩溃时间。

Fatal Python error 的当前崩溃线程没有 Python frame；TLS do_handshake 是同时存在的另一个心跳 Python 线程的快照，不能据此认定 SSL/Supabase 请求是 abort 根因。新版本修复已发现的不安全退出路径，并补足下次定位所需的 Qt 原生原因；不声称已经证明两次现场 abort 的唯一原因。

## 合并基线

GitHub已有v0.23.314（49e1b0a6）发布。本版本基于该提交，完整保留它的source分流、主动喂食反馈、彩雾状态回滚、非daemon心跳、退出等待网络请求及测试；不覆盖已有发布。下面描述最终组合行为。

## 已确认的快捷回归

- window.py `_show_nonactivating` 原来统一调用 `_passive_surfaces_blocked`，不仅挡自动通知，也挡 `show_quick_panel` 和 `_show_work_controls`。游戏、会议、录屏/PPT或另一屏全屏判断均可能挡住用户主动操作；这解释了同代码在不同前台环境表现不同的可能路径，但现有日志不足以确认两台电脑当时的具体前台应用。
- 沿用 v0.23.314 的 `source="user_action"` 分流：双击快捷口袋、右键工作控制、口袋内悬停提示以及主动特效明确标记为用户操作。仅本次动作跳过普通quiet mode，真实全屏、手动隐藏和退出始终不显示；没有关闭全局通知保护。
- `_switch_managed_local_effect` 在v0.23.313切换已隐藏的效果后不 show；保留v0.23.314的 `_start_color_mist_world` 显式恢复及失败回滚。实际全屏/手动隐藏仍会隐藏效果，帧更新不会重新显示。
- 样式、最终几何与 WS_EX_NOACTIVATE 仍在 show 前设置，未添加 activate/focus/grab/SetForegroundWindow。

## Qt 退出风险与诊断

- qt_lifecycle.py：`wait_for_thread` 不再在 isRunning=False 时忽略 wait(0) 结果；`running_threads` 也覆盖原生线程清理尚未同步完成的情况。
- alarm_audio_service.py：旧 clear 在 aboutToQuit 中等1000ms后无条件继续；现在只发停止命令。`prepare_audio_shutdown` 在 QApplication.quit 前确认所有全局音频工作已 wait(0) 完成；未完成则保留对象和事件循环，由应用250ms重试。
- app.py `_continue_quit` 增加音频门禁；`_install_qt_message_diagnostics` 安装一次 Qt message handler，本地日志含 severity/category/function/线程/原生message，fatal 同时写入 native-crash.log 并导出线程快照。回调不操作 Qt/UI、不上传日志。
- program_updates.py：release_notes 不参与 dataclass repr，避免一次更新检查输出整份累积发布史；下载与界面说明不变。
