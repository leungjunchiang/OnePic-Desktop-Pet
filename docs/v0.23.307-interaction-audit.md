# 免战额度、互动收件箱与主动窗口审计

## 免战硬限制

- 北京时间自然月最多8个不同免战日。服务器以真实 `occurred_at` 的北京日期生成不可撤销的 `lili_rest_day_usage(user_id, beijing_date)` 使用记录；该表启用RLS且客户端没有直接读写权限。
- 所有 `rest_day` 的插入/更新（包含旧 `lili_discipline_sync`、增量同步和按钮RPC）经过同一个数据库触发器。同一账号事务锁与现有纪律revision锁使用同一键，避免双设备同时越额或交叉锁顺序。
- 同日取消只增加取消事件，不删除使用记录；同日重挂不再次消耗。`lili_is_rest_day` 按最后一次真实动作判定当前状态。固定休息日不能新增使用记录。周目标不变。
- 老数据按原始时刻推导北京日期回填使用表，保持原纪律事实。升级前已超过8天的月份保留历史，剩余额度为0，阻止新增日期，不删除历史记录。
- 本地仅缓存日期集合，跨设备以服务器快照为准。进入专注/今日、首次配置读取、实际挂牌时读取；没有每分钟计数上传、没有quota轮询。客体动作最终由服务器再次检查，另一设备竞争用完额度时会给页内错误。

## 互动中心

- `InteractionFeed` 按待回应/今天/更早分组，内容决定高度；空页只显示短文案和返回首页入口。原搭子/投喂/成果邀请卡的接受拒绝继续复用，正式训导只显示摘要并导航到现有处理界面。
- `lili_interaction_feed` 是原始 visit/nudge/case/room/taunt/encouragement/buddy 表的只读投影；没有重复存计划、专注汇总或完整报告。正式事项以最后真实action ID识别，暂停/在线状态修改revision不会制造互动。
- 查询最多30条，普通历史保留最近7天，仍待处理的旧邀请/事项可保留。一次UNION和一次profile JOIN，无逐条sender RPC。已读使用私有receipt表，不修改邀请/训导处理状态。
- 第一次成功读取建立服务器baseline：历史不记未读，待回应仍保留；后续新事件未读。进入页面批量标记已读，跨设备共用receipt。自己发出的申请不算未读、不进入待回应，可在Feed撤回。
- 页面进入/主动刷新读取；自习室可见时复用现有dashboard回调，最多60秒发一次Feed读取。没有新增后台轮询timer，隐藏自习室不读取Feed。看过有未读时额外发一次批量receipt RPC。服务器限制每次最多30个ID且核对接收者。
- 回加油/嘲讽/串回去/回请咖啡/小红花复用既有业务RPC及worker。知道了是页内反馈；去开工仅导航，不能替用户或远程自动开工。

## 主动窗口审计结果

完整构造位置清单见 `v0.23.307-popup-inventory.md`。项目使用PySide6，不存在Tkinter Toplevel/after。

1. 清单包含实际独立窗口类构造及QMessageBox/QInputDialog入口，不把普通widget.show误算为独立窗口；包括手动打开的聊天、设置、报告、账号、输入与删除确认。
2. 用途分为主宠物及其关联气泡/进度牌、用户打开的工具窗口、用户设置的闹钟、专注中断恢复卡、即时互动通知、输入/不可逆确认。多数构造入口由用户点击，不能全部视为自动通知。
3. 启动创建主宠物和隐藏的附属组件；社交、提醒、训导首次成功读取只建baseline和恢复内部状态。自动更新检查已有manual标志，启动不弹更新确认。自动日报调用 `show_dialog=False`。
4. 社交dashboard/提醒事件由原30秒调度读取，纪律增量复用原60秒同步；这些只是观察器，只有baseline后新ID且合法时刻的即时事件才进入通知。持续嘲讽/加油状态不朗读旧消息、不启动循环弹话。
5. 已核对原scheduler为窗口拥有的QTimer，页面延迟构造只执行一次；进入页面不会新建一条长期提醒循环。新NotificationManager仅一个单次350ms合并timer，关闭/切账号统一stop。
6. 旧渠道分别有独立已见集合，搭子提醒还允许堆4个窗口；已收敛到一个manager的 `shown_event_ids`，所有渠道共享最多一个当前窗口。接收邀请原本show/raise/activate的独立处理窗已移除主动路径。
7. 旧Toast虽有展示前正文检查，各调用方仍分散创建。现在在构造之前就拒绝空标题/正文/ID，不会创建空壳。
8. 已有每用户QLockFile及进程内真实窗口所有权保护，单实例测试继续通过。使用不同系统用户各自运行属不同账户环境。
9. 保留真正新到达的邀请、训导要求和订阅的真实开工/下班事件；普通互动约3秒，用户长期订阅仍保留既定最长3分钟的提醒时钟。勿扰只抑制展示，不删除订阅/事件。
10. 普通成功反馈（账号、房间、投喂、经济、待办、更新检查）改为已有状态标签/气泡或有父级的短暂标签，不创建系统信息框。删除/注销等确认和严重错误保留modal。
11. 社交邀请、训导提示、订阅提醒共用NotificationManager。自习室前台用页内状态，后台用一个被动Toast；用户点击才打开窗口。Windows复用NOACTIVATE、SW_SHOWNOACTIVATE和SWP_NOACTIVATE，Qt亦禁止接受焦点。
12. 历史社交/训导/订阅恢复不弹桌面Toast。持续纪律继续头顶卡/进度牌/记录；用户显式配置的本地闹钟及已有专注中断恢复卡是独立功能，不当作互动历史重新发送。闹钟已移除主动激活调用，恢复卡也禁止接受焦点，不进入Toast队列。

## 生命周期与边界

- Toast有自动关闭、×/右键关闭、hover暂停和用户点击导航；dismiss销毁引用，退出/切账号清空manager。关闭通知不取消订阅。
- 原生系统Toast不是此次新增功能；使用既有跨平台被动浮窗。全屏/系统勿扰和软件勿扰只记录事件，不补弹历史。
- 可见自习室的Feed最多60秒更新；隐藏时不拉取整个收件箱，因此未读数字在下次打开/刷新更新。此版本没有增加Realtime连接或高频后台请求。
- 旧版本对新额度冲突会收到服务端拒绝，建议所有设备升级；异常网络下缓存可能暂时落后，服务器决定是否真正挂牌成功。
- 测试和真实数据库回滚门禁覆盖配额、同日取消重挂、跨月/时区、旧写入口、baseline、已读/待处理分离、归属隔离与窗口关闭。安装包构建由已有三平台流水线完成。
- Windows 原生验证直接检查新通知与无声测试闹钟自己的窗口样式及前台 HWND：显示、替换、关闭全过程保持前台窗口不变；通知具备 WS_EX_NOACTIVATE，闹钟同时保留任务栏入口。测试窗口透明，不读取其他应用内容。
