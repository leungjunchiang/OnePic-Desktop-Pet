# v0.23.319 · 搭子互动始终接收，免打扰消息首次处理生效

## 行为

- 搭子互动始终开启。我的页面只选择欢迎互动、专注优先或消息免打扰；不存在拒收开关。
- 消息免打扰期间，普通互动进入互动收件箱；不播放嘲讽、加油、投喂等到达效果，不弹桌面窗口。
- 接收时的 `received_silent` 独立保存；当前模式后来变化不改变消息的接收语义。
- 首次点击回应/知道了，服务端锁定事件并设置 `handled_at`，再启用原效果。两个设备同时处理或刷新后再次点击不会重新启用。
- 打开互动页只是已读。串门/投喂邀请的“去处理”只打开申请；实际接受或拒绝才算处理，拒绝不会播放效果。
- 欢迎模式收到的普通消息保持原有处理；历史消息不补标成免打扰收到。
- 嘲讽复用现有二十分钟连续专注状态，加油复用工作中的加油状态；空闲时处理加油给四秒反馈，不自动开始专注。投喂复用已有社交食物效果，不重复扣除库存。

## 修复位置

- `supabase/direct_interactions.sql`：移除 DND 拒收条件，保留搭子关系、原消息归属、日间嘲讽限制、操作幂等和训导权限隔离。
- `supabase/interaction_delivery.sql`：独立 RPC 专用表、接收模式触发器、静默反应暂存、首次处理行锁、邀请处理标记及仪表盘小型修订号。
- `supabase/interaction_center.sql`：原批量查询返回静默/处理标记；激活已有消息产生的反应事实不变成第二条互动。
- `supabase/presence_lifecycle.sql`：已有仪表盘附带消息修订号和批量投影，不增加 HTTP 请求或心跳字段。
- `social_ui.py`：强制接收展示、异步首次处理后回应、账号切换防护、失败按钮恢复、静默食物不自动接受。
- `interaction_center.py`：静默提示和所有首次处理按钮的等待/成功状态。
- `window.py`：复用原反应状态和六毛内部四秒提示，不创建新窗口、不激活前台；全屏隐藏规则继续有效。

## 数据兼容与请求

旧账号 `allow_visits=false` 转为 `allow_visits=true + do_not_disturb`，原安静偏好保留为收件箱静默。旧客户端再次提交 false 也转换为静默；新客户端保存其他资料省略该字段。已有正常互动不回放、不更改其接收方式。无专注数据、工作报告或历史时长重置。

只对尚未处理的静默消息首次主动回应增加一个轻量 RPC。已处理、正常消息照旧。接收与处理修订号通过原低频仪表盘传递，索引读取最后变化的事件；不新建轮询，不逐条请求发送者，继续复用最近七天最多三十条的缓存列表。

新表启用 RLS、显式拒绝客户端直接读写，仅接收者可通过锁定 `auth.uid()` 的 RPC 处理自己的事件；反应子事实不会出现在收件箱或重复增加未读。发布原子 SQL 包包括这次表/函数变化。
