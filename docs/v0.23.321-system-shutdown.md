# 系统更新重启退出修复

## 原因

应用没有独立的系统会话结束处理。`PetWindow.closeEvent` 把普通关窗解释为隐藏到托盘、忽略关闭事件；真正退出又持续等待非 daemon 心跳 HTTPS、Qt 工作线程和音频线程完成，250ms 反复重试，没有系统退出截止时间。`DesktopPetApplication.run` 还会在没有显式退出标记时重新进入事件循环，恢复窗口。以上路径不适用于 Windows 系统结束会话。

## 改动

- `system_shutdown.WindowsSessionShutdownBridge` 由应用持有、安装为全局原生消息过滤器，先于 Qt 的普通关窗兜底处理。`WM_QUERYENDSESSION` 直接返回 TRUE，不做网络、文件保存或窗口操作；`WM_ENDSESSION(FALSE)` 仅清除查询状态，不停止专注。`WM_ENDSESSION(TRUE)` 才执行一次确认退出，即使多个 HWND 都收到消息也不会重复封口。
- `DesktopPetApplication._confirm_system_shutdown` 设置系统退出标记，停止窗口周期计时器和心跳调度，调用 `shutdown_work_timer(system_shutdown=True)` 与位置配置保存。绕过普通关闭、后台线程等待、Qt/音频析构与重进事件循环。
- `ConfirmedShutdownDeadline` 在本地 I/O 前启动独立 daemon 看门狗。保存完成后约 50ms 结束进程；文件系统卡住时最多等待 3 秒。使用 `os._exit` 仅限系统已确认退出的情况，避免 Python/Qt 析构仍运行的 TLS / QThread。普通用户退出仍等待原生线程安全清理，未改变此前 TLS 崩溃防护。
- 普通退出对更新线程改为零等待完成检查、250ms 异步重试，避免此前一次可阻塞 GUI 18 秒，导致系统关机查询迟迟无法被处理。等待中的线程不销毁；完成后才清理，并移除应用拥有的原生会话过滤器。
- `PetWindow._record_focus_segment(sync_remote=False)` 复用现有 FocusSegment/WAL、计时游标、经济账本和本地日统计，不启动经济同步或社交刷新。随后直接暂停 `WorkTimerModel`，不触发 FocusSession UI 信号；重复调用不会重复计入时长。封口异常仍尝试持久化暂停状态。
- 系统已确认退出后的后续 closeEvent 直接接受，不隐藏到托盘、不进入重试。系统退出不追加最终 offline HTTPS；其他设备沿用 120 秒 TTL。普通手动退出继续有最终 offline。

## 数据边界

不修改数据库结构、服务端配置、FocusSession 历史或重置卡。已封口但未 ACK 的稳定 segment ID 保留在本地，下次启动复用原增量上传流程。正常本地写盘成功时保留最后几秒；若磁盘不可写或停顿超过系统截止时间，恢复至既有最近耐久 checkpoint / WAL，不阻止整个电脑重启。macOS 不安装 Windows 消息过滤器，继续原有退出路径。

## 验证范围

新增测试覆盖系统查询/取消、多个窗口重复 ENDSESSION、回调失败仍不否决、GUI 不处理事件时独立截止时间、系统路径不等待 worker/不关闭窗口、本地 407 秒封口与两小时后恢复、不重复上传、不启动网络或 UI 更新、封口失败仍暂停计时。

Windows 原生子进程测试使用真实隐藏 QWidget HWND、SendMessageW 和原生事件过滤器，模拟 QUERY/CANCEL/CONFIRM；同时阻塞 GUI 和保留非 daemon 传输线程，确认子进程限时退出及计时已暂停。没有调用真实系统关机/重启命令，不能替代实机 Windows Update 重启验收。发布仍通过三平台完整测试、打包和既有隐私门禁。
