## 已确认及修复

- 新增回归在旧代码上重现：第 30 首最后 2.4 秒至完整时长收到 QQ 的 Paused，墙钟到期后仍返回换轮。Windows 原生队列现在任何 Paused 都撤销自动续播，清除曲终证据，不用等候时间推断用户意图。
- 自动换轮只接受同一首、同一完整时长、此前真实曲尾播放、停止位置距完整时长不超过一秒，且超过完整时长截止点并连续稳定 1.2 秒的 Stopped。普通曲终仍由 QQ 原生衔接，不重发下一首。若其他 QQ 版本只公开 Paused 作为队尾，保守停播，需要用户主动继续；不能牺牲暂停意图猜测换轮。
- Mac 单曲适配将暂停的曲终位置要求从最后 200ms 收紧为时间轴恰好到完整时长。AX 通常只有秒级时间和播放按钮，无法证明用户在显示的最后一秒内哪一毫秒暂停；这是接口精度限制，不宣称全部消除这种歧义。
- 原生队列同一位置连续停止三十秒会一次提示并停止本机自动续播，保留歌单，用户可点下一首或重新随机。Playing、缓冲、媒体缺失或进度变化重置停止计时。没有将普通缓冲、Paused 或无法区分的用户 Stop 变成自动重播／跳曲。

## Windows 辅助进程

已复核 [失败的 push CI](https://github.com/leungjunchiang/OnePic-Desktop-Pet/actions/runs/40161377114)：确实是无 QQ 的 `probe` 在约六秒失败。
[同提交的 dispatch CI](https://github.com/leungjunchiang/OnePic-Desktop-Pet/actions/runs/40161392730) 成功。旧记录没有阶段耗时，不能据此断言卡在导入、COM 初始化还是 UIA 根控件读取。

现在给辅助进程启动／UIA 导入初始化独立的十五秒预算；进入操作后，读取最多六秒、设置最多十秒，整个请求分别不超过二十一／二十五秒（加辅助退出清理）。阶段变化不会不断延长预算，也不重试模式命令。取消约四十毫秒轮询优先，仅回收本次自有 helper，不终止 QQ。

阶段包含导入、COM 初始化、就绪控件、模式控件、原生命令、模式回读及 UIA 动作，记录相对毫秒、请求状态和退出码。日志仅保存固定阶段与耗时，不含账号、路径或原始控件树；成功保留在后端诊断并以 debug 记录，失败以 warning 记录。COM 初始化上下文保持到操作结束，不能初始化后立即释放再复用原生指针。

首轮发行门禁捕获新增进度文件的 `PermissionError`（处于初始化后、操作标记写入前）。Windows 读取旧进度时可能短暂拒绝原子替换；诊断写入已改为容错，失败次数留在最终回复，绝不能把诊断锁竞争变成 QQ 操作失败。新增注入共享冲突的回归，最终结果仍必须可靠回传；不通过重新运行失败构建来掩盖此问题。

未确认播放的提示不再将媒体信息缺失、暂停或版本不一致归为登录／会员问题；本地日志记录选定及观察到的歌曲元数据，便于后续定位。它不证明账户已退出，也不会触发重新登录。

## Mac 版本核对

搜索结果必须匹配完整版本标题、歌手以及已知专辑。嵌套 AX 节点指向同一按钮只算一个结果；多个不同播放按钮时不再点击第一个。搜索结果等待限时八秒，失败保留阶段说明。

播放栏若提供带 album 标识的字段，会读取并严格核对非空专辑；出现多个独立播放栏则拒绝伪造唯一播放状态。自检说明是否能读取专辑，不导出账号文字。

仍保留可信 AX 播放栏缺专辑时的兼容规则，因此不能仅凭该栏证明精确歌曲 ID 或同名专辑版本。没有真实已登录且授权的 Mac 可用，不能把模拟回归、原生框架导入或两种 DMG 构建当成 QQ 连续播放验收。Mac 在线功能继续标为试验适配。
