# v0.23.312 直接互动与房间边界审计

## 根因与代码位置

并非所有互动都要求房间。`SocialHubDialog._send_interaction` 原先仅专门处理 visit 和 cheer：收到的“嘲讽回去”传入 taunt 后落入 `_send_room_interaction`，没有 current_room_id 就显示持久红色错误。cheer 又会依据对方状态变成嘲讽，或在旧鼓励接口缺失时回退到房间。`_interaction_response` 的花朵回应误用 `lili_supervision_nudge`，混入了正式训导授权。回应按钮未关联异步请求完成状态。

已修改 `social_ui.py` 的 `_interaction_response`、`_send_direct_interaction`、`_send_interaction_rpc`、`_send_interaction`、`_set_status` 及卡片 `_request_reaction`。`interaction_center.py` 的 `InteractionFeed._respond` 复用 ui_feedback 的 begin/end_button_work，跨 render 保留请求状态；完成回调不进入缓存或 RPC。`window.py` 的 `_send_food_interaction` 复用现有余额预留、成功扣款、经济事件队列、账号隔离 worker，补上原事件引用和按钮完成回调。

## 八项核查

| 核查 | 结果 |
|---|---|
| 原来为什么被要求房间 | 未识别的回应 action 落入房间入口；服务端旧 lili_send_interaction 也拒绝 null room |
| room_id 是否必填 | lili_room_events.room_id 仍为 NOT NULL；直接互动复用没有 room_id 的 lili_visit_events |
| direct / room 是否区分 | p_room_id=null 为 direct，服务器写入 payload.scope=direct；非 null 仍调用 lili_record_room_event 并检查成员资格 |
| 回应对象 | 直接取收件箱原行 sender_id，不按昵称、当前选中的搭子或房间推断；RPC 内再次验证原事件 receiver/sender |
| 普通搭子互动 | 加油、轻嘲讽、夸赞、敲桌、催开工、小红花和回请直接发送；原有串门及食物接口本已无房间限制 |
| 仍需房间的内容 | 房间短语、房间动态、加入/离开、共同计划/目标/挑战、房间成员活动；正式训导继续使用独立权限接口 |
| 嘲讽回去请求数 | 有效登录时 1 次 lili_send_interaction 写入 RPC；无客户端原事件、共同房间、成员或刷新读取。过期登录可能另有正常认证刷新；页面已有后台同步不计入点击请求 |
| 删除的查询与回退 | direct 回应不调用房间验证/读取，不在成功后刷新房间；缺失鼓励接口的兼容回退也改为 direct |

## 数据兼容与授权

`supabase/direct_interactions.sql` 是现有部署脚本的可重复执行组成部分。扩展已有 visit kind CHECK（保留全部食物/蛋糕分享旧类型），增加仅对 direct 操作键生效的查询索引；没有新业务表。新增同名四参数 RPC 的 p_payload **没有默认值**，与旧三参数函数按参数集合明确区分。旧三参数函数兼容原房间调用，也允许无房间普通直接互动。现有 relay 已允许该函数名并原样转发 body，无需新网络路由或部署新的 Edge Function。

已有 payload 保存 reply_to_event_id 和 operation_key。同一用户操作键加事务锁；网络重试返回原 ID，不重复投喂；同键更换目标/类型/原事件被拒绝。普通即时互动存 accepted，串门与投喂仍按既有邀请流程处理。food_cake_share 等旧数据不改写。

服务端验证登录、非自身目标、已接受搭子关系、目标 profile 存在、allow_visits 与 do_not_disturb、动作白名单；有原事件引用时验证它确实由目标发送给当前用户。当前系统没有独立拉黑表/字段；删除/拒绝关系、关闭接受互动、勿扰按现有数据拒绝，不能靠历史事件恢复关系。只静音通知的 muted 不等同于拉黑，沿用原有语义。

严格训导动作不在普通动作白名单，仍走原授权、审查和结案接口。花朵回礼是轻互动，不产生正式训导奖惩。轻嘲讽保留北京时间 08:00–22:30 隐私限制；回应无需同房间，但不会绕过关系撤销、隐私设置或此时间规则。主动工作中加油仍复用既有鼓励接口。

## 生命周期与流量

回应按钮立即显示“正在发送…”，禁用自身；同目标同动作也有 worker 防重入。成功显示“已回击/已回请”等约两秒，失败恢复，刷新重建时沿用未完成状态。账号切换后的旧响应不更新新账号数据，finished 仍清理按钮/食物价格预留。普通错误四秒后隐藏，新状态取消旧计时；重新登录提醒仍保留。

回请仍发送一次互动 RPC，成功后按原经济账本另有低频记账同步；未发送成功不扣款。没有新增配置轮询、读回确认或按卡片查房间。收件箱原有最近七天/最多三十条、北京日期分组、缓存/新事件合并、历史静默恢复保持生效。

## 验证与边界

`tests/test_direct_interactions.py` 覆盖 sender 继承、四种非投喂回应、无房间单请求、失败恢复、重建按钮、防连点、成功驻留、账号切换、普通动作和回请余额/扣款/清理。现有 social_ui、互动和完整测试继续执行。

发布前部署执行 `scripts/verify_direct_interactions.sql`：实际 PostgreSQL 合成账号事务回滚，覆盖无房间、旧三参兼容、房间来源回应、原事件伪造/目标篡改/所有权、非搭子、撤销关系、勿扰、严格权限拒绝、投喂幂等与重复部署。仅改函数与已有表约束/索引；不读取用户个人互动作验证。

发布 CI 构建 Windows 和 macOS 两种架构，附安装包、校验和与公开资源清单。GUI 自动化使用本地测试客户端；真实双方账号端到端点击仍需用户安装后确认，但实际服务端授权由上述回滚测试验收。
