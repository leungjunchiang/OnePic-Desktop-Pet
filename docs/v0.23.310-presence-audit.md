# v0.23.310 在线与活动状态审计

## 找到的原因

1. `SocialHubDialog.apply_dashboard` 将本地计时叠在 `me_presence` 上，只设置 `online=true`，仍继承旧服务器心跳、`stale_presence` 等字段；统一 TTL 会把自己的卡片判离线。现使用当前本地状态与时间，明确清除远端过期标志。
2. `_presence_status` 只有 focus / rest / offline，没有在线 idle；非工作统一变成休息。现显式解析 activity，并保持 TTL 优先。
3. `PetWindow.closeEvent` 不区分关窗与退出，一旦收到关闭事件就停止所有调度。Application 现在为实际宠物窗口启用 close-to-tray，只有明确退出设置 `application_exit_requested` 后清理。
4. 退出最终请求只是 `working=false`，服务器仍将该设备登记为活着，并且 daemon 网络线程可能还未完成进程就结束。现提交显式 offline，Qt 每250ms检查最终请求完成，最多等待15秒，期间不在界面线程执行网络 I/O。

未发现 `hide_pet`、`hideEvent`、最小化或关闭自习室会直接停止心跳，也未发现没有 FocusSession 就停止心跳。不可把这些推测当成已确认根因。

## 生命周期、频率与字段

| 检查项 | 现在的实际行为 |
| --- | --- |
| 心跳所有者 | PetWindow 持有一个 `SocialHeartbeatWorker`，认证后启动；Python线程不依赖页面或Qt事件循环 |
| 重复启动 | `start()` 检查同一个底层线程是否活着；页面重建不创建心跳 |
| 无专注、结束本轮 | presence=online，activity=idle |
| 专注、暂停 | presence=online，activity=focus / rest；原始 FocusSession 区间不变 |
| 最小化、隐藏、托盘、失去焦点 | 心跳继续；不根据可见性或焦点判在线 |
| 频率 | 15秒；状态变化可以即时发送；后台统计读取继续使用90秒缓存门控 |
| TTL | 120秒。失联、强制结束、断电、断网都会由TTL回落离线 |
| 正常退出 | 停止Qt调度，当前设备最终offline请求，异步等ACK后结束进程；不删除该设备序列栅栏 |
| 网络恢复 | 原工作线程继续重试，原鉴权恢复和60秒ACK健康检查仍保留 |
| 自己的界面 | 当前本地状态，不执行写后SELECT确认 |
| 搭子显示 | 共用 `_presence_status`，focus > rest > online > offline；离线优先于旧活动 |
| 最后确认 | 在线首页卡隐藏该行；离线或未知时显示。详情仍提供诊断时间 |

新版 Direct 心跳一次POST `lili_presence_heartbeat`，实际请求仅9个RPC参数：

```text
p_presence_state, p_activity_state,
p_working, p_session_active, p_session_id, p_session_started_at,
p_device_id, p_sequence, p_input_idle_seconds
```

账号从Bearer认证取得，`last_seen`由数据库时钟生成。没有今日/本周累计、完整FocusSession、计划、订阅、训导授权、纪律、闹钟、互动历史或娃衣。没有增加写后查询；原轻量ACK保留序列与设备/账号聚合，便于安全重试。原来的心跳已经过滤大字段，本次没有把不存在的大字段上传描述成已删除问题。

`input_idle_seconds` 是已有的聚合输入证明，不包含按键、窗口或应用历史；缺失/过期输入证明仅限制实时专注投影，不改变在线存在。自动暂停是现有独立业务策略。

## 服务端与兼容

- `supabase/presence_lifecycle.sql` 为原设备表和账号兼容投影各增加 `presence_state` / `activity_state`，没有新增事实表或改FocusSession。
- 复用原 `lili_upsert_focus_presence_core` 的账户事务锁、设备递增序列、会话一致性、聚合逻辑；增加显式在线设备过滤。
- 复用 v2 输入证明与会话隔离门禁。旧客户端继续调用 v2；缺少 activity 的旧非工作心跳兼容为休息，仍在线。安装新版后可以明确区分idle。
- 设备退出只关闭该设备，另一个仍有新心跳的设备继续在线；乱序旧请求不能复活退出设备。
- dashboard / room dashboard 在已有授权结果上批量聚合设备状态，保留隐私过滤、统计与名称，无客户端逐个搭子查询。历史过期设备统一离线。
- 私有触发器、核心函数与展示辅助函数不授予匿名或客户端调用；公开心跳显式检查 `auth.uid()`，保持原RLS，隐藏用户不会泄露在线状态或时间。
- 原子发布脚本同时部署结构、RPC与兼容投影，并执行真实Postgres回滚fixture。部署失败阻止Release。
- CloudBase代理源码同时兼容新旧协议；当前发布使用Direct路径。若自行部署旧CloudBase代理，需更新本仓库代理源码才支持新版显式状态。

## 验证与边界

新增 `tests/test_presence_lifecycle.py` 覆盖真实Qt窗口的开始/暂停/结束、最小化/隐藏/关窗、后台无FocusSession心跳持续、重复start、退出异步等待且只写一次、自己继承旧离线快照、三类活动的TTL及排序、精简字段和旧协议兼容。

`scripts/verify_presence_lifecycle.sql` 在真实数据库以合成用户验证：idle/rest/focus、缺失输入证明仍在线、双设备分别退出、乱序序列、121秒TTL、恢复、旧v2、dashboard标志、隐藏状态、匿名拒绝及私有RPC权限；全部回滚，不读取真实用户记录。

这里“立即离线”表示服务端成功收到正常退出请求后立即更新，其他搭子界面在下一次既有批量刷新显示，不承诺实时推送。无法上报的断网/强杀由120秒TTL处理。网络超时最多等待15秒后退出，避免无限卡住。
