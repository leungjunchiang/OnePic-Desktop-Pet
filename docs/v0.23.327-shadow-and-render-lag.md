# v0.23.327 · 透明窗系统阴影与 GUI 卡顿

## 证据和边界

用户确认 Windows v0.23.326。运行日志也记录 current=0.23.326；lifecycle.log 在同步应用后记录 938ms 和 906ms 的 GUI event loop lag。

透明的 PetWindow 和控制气泡没有明确禁用原生窗口阴影；本次补齐 NoDropShadowWindowHint，避免系统对动画轮廓/透明工具窗口添加外围阴影。未拿到黑色外圈截图，无法据此排除显卡或桌面合成器的其他因素，不能说日志直接证明了黑圈来源。

性能重放只读取用户现有 1803 条事实并在 persist=False 的内存副本上计算，没有写回账号数据。旧显示合并使用每个区间遍历全部既有区间的 any()，重复约平方级查询；本机三次平均约 459.93ms，ID 索引版本约 0.66ms。

主计时还反复构建完整 day/week 报告。新增 include_details=False，复用相同日历、并集、legacy 最大值和不可信记录隔离计算，只跳过报告特有的质量、会话分析和最强时段。解析区间在同一次报告中复用，不缓存未经验证的新事实。今日/本周重放由 174.12ms 降至 86.96ms。真实账本日/周/月/年累计和证据字段均与 v0.23.326 一致。

## 修改位置

- window.py：本体和 ambient flags 禁用原生阴影；显示区间合并改为线性 ID 索引；计时与停止后的本日校准只取轻量投影。
- controls.py：控制、时长、提示窗初始 flags 也禁用系统阴影，避免第一次显示到置顶切换之间策略不一致。
- focus_analytics.py：共享同一 period_summary 计算，完整工作报告默认行为保持；focus_aggregate 复用本轮解析后的区间。
