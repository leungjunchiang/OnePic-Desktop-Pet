# v0.23.309 互动日期与提示生命周期审计

## 根因与修改

- `interaction_center.grouped_rows()` 原先只分今天/更早。现在先用 `parse_server_datetime()` 转北京时间，再按自然日期分组；今日及之前六日，跨年标题带年份。卡片时刻同样先解析服务端时间，不再把无偏移服务端时间误当北京墙钟。
- `SocialHubDialog._tab_changed(1)` 原先强制拉取收件箱并触发完整 dashboard 刷新。现在先本地渲染，再仅在首次加载/数据标脏时读取。普通心跳和时间变化不使列表失效；来源签名只含稳定事件字段，不含倒计时。
- 已确认的新 nudge 可以直接合并缓存；缺少新事件明细时只标脏，隐藏页面不发历史查询。进行中的请求使用版本号和账号围栏，防止旧结果覆盖新事件/新账号。
- `lili_interaction_inbox()` 原先是滚动 168 小时，会含第八个北京日期。现改为北京时间今日零点减六日，直到次日零点。一次 RPC 最多 30 条，显式字段加一次 profile join，没有逐日查询或逐条用户查询。未处理邀请仍单独保留待回应语义。
- 旧已读操作再次调用 inbox，返回完整历史。新增 `lili_mark_interactions_read(jsonb)` 仅返回事件 ID 回执及时间；旧 inbox 参数继续兼容旧客户端。无新表、字段或历史记录搬迁。两个 RPC 仅允许认证用户读取/标记自己的事件。

## 提示为何一直存在

`coaching.projection()` 把正在超时的长休投影为“👀 该回来了”，`_refresh_desktop_coaching()` 再附加其他持续事项数量 `+1`。这是持续状态牌，而不是刚收到互动的重复计数，所以没有四秒隐藏计时。修复为明确的“⏳ 长休观察中”，持续补时、欠账、待说明继续按业务条件结束。

真实新互动统一进入 `PetWindow._notify_instant_interaction()`，共用 `NotificationManager.shown_event_ids`，并复用已有 `speech_bubble` 与单次 `speech_timer`：默认 4000 ms。同类再次到达更新计数并重启计时，异类替换；旧事件 ID 不重启计时。隐藏/前台情形继续使用既有无焦点通知或页内反馈，不新建一套窗口系统。没有淡出动画。

加油原先在 `_apply_encouragement_state()` 每次刷新恢复常驻文字，现在只保留一小时娃衣效果；旁边加油文字仅在真正的新事件到达后显示四秒。嘲讽需真实专注赎回的既有挑战仍保留剩余时间，但标签明确为“嘲讽挑战”，不再冒充瞬时嘲讽反馈。实际自习室访客在线状态仍在访客离开时结束。

## 历史恢复与生命周期

- nudges/visits/taunt/cheer 首次成功同步建立 baseline，历史静默；重连、刷新、重新绘制不重播。
- 房间事件补齐首次成功同步基线、时间范围、账号隔离；离线缓存不能建立基线或发提示。
- ID 去重在所有瞬时显示路径共用；勿扰/空正文不创建提示。
- 四秒计数、截止时间和 hide 完全本地，不上传 `shown` 或剩余时间。关闭/换账号时清理计时与提示。
- 原 `show_speech()` 的非激活显示行为保留，未新增 activate/focus/foreground 调用。

## 验证

关键用例覆盖 UTC 跨北京零点、显式偏移、服务端无偏移 UTC、昨天/跨年标题、七个自然日边界、30 条排序限制、切页缓存、主动刷新、新事件合并、首次历史静默、房间离线缓存与去重、重复互动计时重启、四秒真实 Qt 自动隐藏以及旧计时不会提前关闭新提示。

现有全量测试与三平台 release build 为发布门禁。实际 PostgreSQL 回滚 fixture 验证 Beijing 日期范围、最小字段、精简已读回执、跨设备已读不消费待回应事项和账户隔离。发布后安装包、源码提交树与 SHA256 一并核验。

## 边界

无法解析的历史时间显示“日期未知/时间未知”，不伪造归属日期；相应服务端数据需另行修正。收件箱继续受 30 条上限限制。无实时推送的后端仍依赖现有低频同步发现新事件，没有为了此次展示新增轮询。
