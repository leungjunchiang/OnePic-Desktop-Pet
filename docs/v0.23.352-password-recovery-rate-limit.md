# v0.23.352：密码重置限流处理

Supabase Auth 对发信频率和认证请求有不同限制。旧客户端把所有 HTTP 429 显示成“确认邮件次数达到限额，建议配置自定义 SMTP”，会在验证或其他请求受到限制时误导用户。本版按错误码优先区分邮件发送限制和一般请求限制，无法判断的 429 使用一般提示，不推断服务器缺少 SMTP。

在当前重置窗口中，发信成功或被限流后限制重复发送 60 秒；该客户端等待只是减少重复请求，并不能改变服务端及邮件供应商限制。发信失败时，保留之前同一邮箱仍在有效期内的验证码入口；修改邮箱后不能提交旧邮箱的验证码。密码和验证码仍不写入日志或文件。

部署侧只读检查显示项目已配置自定义 SMTP，项目邮件发送限额为每小时 30；网关汇总记录到重置接口 429，状态码不足以判定是何种限流或对应某一用户。配置随时可能变化；如果持续出现，应检查 Auth 日志和邮件服务商限额，必要时按实际业务流量调整，不应关闭邮箱验证来绕过限制。

回归覆盖首次被限流、60 秒冷却、已有验证码仍可用、邮箱绑定和限流文案；未经真实邮箱收信及密码修改验收，无法声称本机账户已恢复。无服务器写入、邮件自动发送或账号操作。
