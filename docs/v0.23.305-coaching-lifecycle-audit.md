# v0.23.305 双向训导核查

## 原实现的边界

原来只有 `lili_supervision_nudge` 轻提醒和 `DisciplineStore.explain()` 本地说明。说明提交即从本地待办移除，没有搭子审核、退回、补时接受及结案状态。`BuddyStudyDialog` 的监督关系页提供催促按钮，未构成双向处置；v304 今日留言卡承接静默恢复消息，但不承担执行状态。

## 本轮数据流

真实的迟到 / 结束后的长休超时 / 结束工作结算缺口 → 正式事项 → 用户说明或接受补时 → 搭子通过、通过加补时、退回、放过 → 专注达标后结案。

普通开始、暂停、恢复和心跳不建立正式事项。白天的动态缺口仍是普通进度。严重且需要说明的当前严格模式结果可由原纪律同步批次建立待回应事项；旧历史读取不批量转成新事项。搭子也可对已结算的真实结果主动处置。

## 状态与权限

- `pending`：写说明 / 接受补时；`rejected`：重新说明。
- `explained`：待搭子审核；`active`：按真实专注执行。
- `completed`：说明通过或补时完成；`forgiven`：直接放过，区别于完成补时。
- 每个来源结果只有一条事项；由首位处理搭子负责后续审核，避免多人覆盖意见。
- 服务端检查本人总开关、范围、双方搭子关系、当前严格模式、说明分享和具体迟到 / 休息 / 计划权限。
- 普通训导不能创建正式事项；用户不能通过 RPC 放过自己的事项；撤权后搭子看不到解释或进行处置。
- 保留关闭训导和退出软件能力；已暂停事项留存历史，暂停期间不要求回应或自动完成。

## 版本、去重与同步

- `lili_coaching_cases` 使用来源事件唯一约束；每个处理动作携带 action UUID 和期望 revision。
- 重试相同动作返回原结果；旧 revision 明确失败，不采用整对象上传或 Last Write Wins。
- 来源规则键同时关联旧设备保留的本地事件 ID，旧说明编辑器和观察牌不会再产生重复入口；较早的真实专注事实更正迟到或缺口后，解除失去依据的事项，保留更正历史。
- 表启用 RLS，客户端无直接表读写权限，只使用检查身份及授权的限定 RPC；内部辅助函数不向匿名 / 登录客户端开放。
- 新结构由既有 discipline migration bundle 在同一事务部署。没有本机 Supabase CLI，不猜测新的时间戳 migration 文件；部署脚本把结构扩展纳入原幂等 bundle。
- `lili_coaching_sync_delta` 复用原纪律同步 worker 和 60 秒运行时检查，事项有独立持久游标，一次最多 100 条变化。普通渲染、每秒计时及心跳不读取或上传事项。
- 监督详情运行时刷新由 10 秒调整到 60 秒；用户操作完成后读取一次。本人授权设置仍按页面进入、保存及主动刷新读取。
- 只同步创建、说明、审核、接受、放过和完成；不上传每分钟 remaining。完成时额外封存一次原专注事实，服务端再次计算并集，网络未确认时显示等待数据确认，随后复用原队列重试。

## 补时与观察期

- 从 `accepted_at` 后的有效 FocusSession 区间并集计算，重叠设备只计一次；暂停不增加，跨午夜不清空进度。
- 通过加补时立即进入执行，直接补时要求仍需用户接受。
- 本周补回可在接受后执行；明天优先补的计时起点为次日自然日零点；周目标仍沿用原动态分配。
- 昨日缺口默认只提供今日 60 分钟观察牌，不把实际缺口改成 60 分钟，也不创建观察期云端倒计时。
- 同时只有一个待回应主卡和一个执行 / 观察牌；正式补时优先于待审核和观察，额外事项显示数量。关闭后历史不删除。

## 日常互动与通知

- 工作、休息、未开工、完成目标的动作按状态提供；增加敲桌子、夸一下、小红花和批准下班，沿用低频 nudge 事件。
- 投喂复用已有四种食品及后台 handler；没有新增钱包、商城或经济系统。
- 存在未处理事项时批准下班提供“仍然放行”，不强制拦截或替用户结束专注。
- 运行期新日常提醒在六毛附近短暂显示约 2.6 秒，首次同步、重连旧消息仍静默。消息 ID 去重，本机留言有已读状态；已读不额外产生服务端请求。
- 持续状态使用头顶卡与进度牌；Windows 使用 `WindowDoesNotAcceptFocus` / `WA_ShowWithoutActivating` 及既有非激活展示。只有用户主动点击才打开回应页或详情。
- 退出及切换账号销毁状态浮层，晚到响应不得更新其他账号。
