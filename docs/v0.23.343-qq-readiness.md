# v0.23.343 · QQ 已登录时的就绪误判与提示

用户报告另一台电脑已经登录 QQ，但六毛仍显示“尚未登录或界面尚未就绪”。
该文案由 Windows 启动检查统一返回，并不证明账号实际退出。旧实现把没有读到
搜索框、播放栏不匹配、UIA 读取异常和登录中／需要登录都导向同一条提示。
目前无法直接访问报告问题的那台电脑，未确认它的确切触发条件或 QQ 版本。

本次修正：

- Windows 就绪条件兼容编辑框、组合搜索框，以及无搜索框但有上一首、下一首和
  播放／暂停或模式控件的播放栏；原生歌单投递本就不需要向搜索框输入。
- 完整播放栏中的普通“登录”静态文字不再单独推翻就绪证据；登录按钮、登录窗口
  标题以及“点击登录”“请先登录”“安全验证”等明确标记仍阻断，不绕过实际登录。
- 展开窗口内离屏的旧登录节点不参与判断。QQ 最小化时根节点的 UIA IsOffscreen
  可能仍为假，因此同时只读核对 Windows IsIconic／IsWindowVisible；后台播放栏
  仍可检测，不为了判断就绪展开、隐藏或移动用户窗口。
- 已运行客户端的登录提示需连续两次确认，允许 QQ 重建界面时的瞬时标签自行恢复。
  真正登录中仍等待，冷启动仍只普通启动一次，不携带歌单、播放或账号参数。
- 登录提示、登录中、播放栏未识别和界面读取失败／超时分别说明；后两者不再要求
  重复登录。未确认时仍不投递、不暂停、不恢复模式、不操作账号。

回归覆盖不同搜索角色、缺少搜索框、普通文字与真实登录按钮、登录标题、隐藏旧节点、
最小化根节点属性不一致、真正登录／验证拦截、瞬时恢复、错误原因区分和隐私字段过滤。
只查询固定就绪标记，不保存账户身份、搜索输入内容或完整界面树。

本机已登录且最小化的 QQ 经真实独立 UIA helper 连续确认就绪；生产管理器成功
随机播放《鹿回头》，按本机三十首列表切至《耍赖》，之后暂停并核对不再推进和静音。
本轮十五首热门、现场六首，测试有独立三十秒守卫。未重复退出／冷启动 QQ 或整曲
曲终测试；登录和原生队列其他行为沿用既有验证。

该结果不能替代另一台电脑的实测；若仍不就绪，修正版提示将区分具体失败阶段，
便于继续定位其版本／界面差异。Mac QQ 在线控制仍为试验适配，本次 Windows 判定
修复不构成 Mac 在线兼容验收；两种 DMG 仍未签名或公证。
