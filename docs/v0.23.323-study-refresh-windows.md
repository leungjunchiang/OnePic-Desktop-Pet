# 自习室刷新临时小窗口修复

## 根因和证据

social_ui.py / BuddyCardWidget.__init__ 原来创建无父 QLabel，然后在布局 addWidget 之前调用 setVisible(True)。Qt 对没有父 QWidget 的控件按顶级窗口处理。备注与公开昵称不同、提醒订阅开启、离线/状态未知的最后确认标签，最多三项分别触发 Show；下一步布局收养又隐藏/重定位，形成多个小窗短暂闪现。apply_dashboard 因成员、备注、娃衣等结构变化重建卡片时会再次执行。无需任何新互动，不经过 NotificationManager，因此原有 Toast no-activate 不能保护这条路径。

修复前使用 QApplication eventFilter 捕获顶级 QWidget 的 QEvent.Show，离线并开启提醒的卡片直接复现独立 QLabel Show。只检查刷新完成后的 topLevelWidgets 会漏掉这种短暂窗口。用户旧日志未记录每个普通 QLabel 的 Show，不能将其某一时刻看到的所有窗口逐一反推；代码与回归已确认这条匹配现象的真实路径。

coaching_ui.py / CoachingPanel.__init__ 的 badge 也原来没有父级；首次 refresh 在调用者把 badge 插入计时旁之前恢复已有训导状态，setVisible(True) 会先显示独立按钮。一起补齐父级。

## 修改

- 所有 BuddyCardWidget 标签、操作按钮明确 parent=self；布局、已有事件处理和状态更新规则保持。
- CoachingPanel.badge 从创建时属于调用者页面；没有外层父级时先属于面板。真实页面之后仍将它插入今日计时旁，正式训导卡折叠不影响进度牌。
- 沿用网络后台 worker，GUI 更新继续在 Qt 主线程。把控件创建移到网络线程会破坏 Qt 线程规则，本次直接消除不应存在的独立窗口。
- 不增加 show/raise/activateWindow/SetForegroundWindow，不新增轮询、日志上传、数据库 migration 或配置变更。

## 验证

tests/test_study_refresh_windows.py：隐藏/显示父窗口下构造卡片都没有独立 Show；恢复训导 badge 在布局收养前已有页面父级；隐藏/显示自习室各反复三次重建卡片，焦点不变，隐藏的自习室不重开。Windows 本机原生插件下反复四次刷新前后的 GetForegroundWindow 一致；测试本身 WA_ShowWithoutActivating，不强制激活用户当前应用。

无头 CI 跳过原生 HWND 检查，用 Qt Show 事件及焦点回归覆盖；原有训导回应、进度牌、工作计划、消息和窗口测试继续执行。没有将正常用户主动打开的对话框隐藏，也没有阻断真正新互动的接收。
