# v0.23.311 全屏悬浮层核查

## 根因与修改位置

`activity.py::_windows_foreground_is_normal_window` 原来在 WS_CAPTION / WS_THICKFRAME 存在时直接排除浏览器，allow_media_fullscreen 没有参与该分支。浏览器在视频/F11 期间保留这些位时，即使窗口完整覆盖显示器也会返回 normal/maximized。回归夹具已复现并修复。borderless 的 IsZoomed 也不再作为排除条件。

原 Win32 调用未声明 HWND/HMONITOR/HANDLE 的参数与返回类型，ctypes 默认 c_int 存在 64 位截断风险。已声明指针类型；宽句柄回归通过。本机实际读取到的显示器句柄未发生截断，因此不将该风险说成本次 Bilibili 的已证实原因。

没有取得用户出现问题时的前台 HWND、样式与矩形；不能认定真实 Bilibili 当时必然走了上述分支，也不能宣称已操作真实网站/PPT 实测。

`window.py::_fullscreen_surfaces` 原来漏掉头顶训导卡/进度牌；`_finish_fullscreen_restore` 没带 pet HWND，可能混用 Qt 逻辑像素与 Win32 物理像素；旧恢复映射会重新 show 已过期的 speech_bubble。已补齐、统一并剔除瞬时恢复。

`NotificationManager.suspend_display` 关闭当前通知和排队显示，保留 baseline 与 shown_event_ids，避免退出全屏重播。`DesktopCoachingSurface.passive_show` 直接走 owner 显示门禁，不再先无条件 show。

## 用户要求的十项结果

| 项目 | 当前实现与证据 |
| --- | --- |
| 1. 检测方法 | GetForegroundWindow → GetAncestor(GA_ROOT) → DWM extended frame bounds（失败回退 GetWindowRect）→ MonitorFromWindow/GetMonitorInfoW；比较完整 rcMonitor，四边容差 4px。保留桌面/任务栏 shell 排除和隐藏/最小化排除。 |
| 2. Bilibili 漏判 | 已确认代码中浏览器保留 caption/frame 时的提前否决；合成同样样式与全屏矩形可复现。实际用户现场未采样，不能断言唯一原因。 |
| 3. 原来只识别 maximize？ | 不是。原来已比较窗口/显示器矩形，但之前的样式/IsZoomed guard 可在几何判断之前退出。 |
| 4. 是否有置顶 watchdog？ | 有，已有低频约 3 秒 watchdog。 |
| 5. 是否把隐藏后六毛顶回来？ | 原 watchdog 已检查全屏/可见状态，SetWindowPos 没有 SHOWWINDOW；未发现它会主动 show 隐藏的本体。现又在 _ensure_on_top / native policy 入口加门禁，并补齐附属层；运行 watchdog/刷新/互动测试仍隐藏。 |
| 6. 全屏时降层还是隐藏？ | QWidget.hide，保留对象；所有被动宠物附属层隐藏，当前独立 Toast 关闭，不 destroy 宠物。 |
| 7. 退出后恢复 | 原位置、原 topmost 设置、进入前可见的持续附属层；计时和训导牌根据当前本地事实重算。瞬时 speech/特效/独立通知不补播。用户手动隐藏仍优先。立即及 150ms 延迟原生层级修复均不激活窗口。 |
| 8. 多显示器 | foreground/root HWND 与 pet HWND 的 MonitorFromWindow 句柄一致才抑制。Win32 原生身份优先于 Qt logical geometry，125% 等缩放不误判其他显示器。 |
| 9. 检测周期 | 一个应用级 QTimer，750ms；普通轮询连续两次相同结果后切换（约 0.75–1.5 秒）。显式显示/应用生命周期与 watchdog 的安全检查可立即执行，防止主动显示穿透。只在状态切换时恢复；无重建。 |
| 10. 远端请求 | 检测、隐藏、恢复、去重与生命周期全部本地；无 Supabase 查询/上传、无数据库迁移；原心跳/专注同步不因 hide 停止。持续状态恢复复用已加载纪律引擎，避免新建引擎重置通知基线。 |

## 验证与边界

- 回归覆盖 Chrome/Edge/Firefox 的普通最大化与保留样式的真全屏（Bilibili/YouTube/F11 同类几何）、VLC/PotPlayer/PPT、未知 borderless、DWM 回退与 4px 容差、GA_ROOT、64 位句柄、不同 monitor 与125% 同 monitor。
- 真实 Qt PetWindow 覆盖双向 debounce、原位置恢复、全屏期间 watchdog/native policy/状态刷新/新通知保护、训导附属层、手动隐藏、延迟恢复重新全屏、瞬时提示不重播与通知 baseline/ID 保留。
- 本机真实 Windows API/Qt 窗口验证：普通→normal，最大化→maximized，真实无边框全屏→fullscreen；DWM rect 与 monitor 都是 3840×2160，work area 为 3840×2080。宠物原生 IsWindowVisible 确认隐藏；退出恢复，前台 HWND 未改变。验证只创建自己的临时窗口，未更改现有软件。
- 本机只有一块物理显示器；双屏用原生句柄模拟回归覆盖。没有操作实际 Bilibili/YouTube 网页、PowerPoint 文件或独占游戏进行端到端实测。
- 完整覆盖屏幕仍保留普通样式的未知应用、自动隐藏任务栏导致 work area 等于 monitor 等边界，可能不能仅靠窗口几何完全区分普通最大化与真全屏。保留普通 framed 应用的保护、已知媒体/演示与 borderless 全屏识别，不读取网页内容/窗口标题或依赖云端。
- macOS 原有 Quartz 显示检测保留，应用层统一隐藏保护/瞬时恢复修复同时适用；没有改写 macOS Spaces 判定。
- 仓库没有配置独立 lint 工具；检查语法编译、git diff --check、完整测试与既有发布包/隐私门禁。发布流水线 Windows、macOS ARM/Intel 全部测试后构建，并核对发布源码树、九个资产及四组 SHA256。
