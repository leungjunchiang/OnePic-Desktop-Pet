# v0.23.338 · 保留 QQ 窗口与 Mac 适配检查

原有后台回调在播放确认轮询和后续投递时反复隐藏 QQ，导致用户已经打开的
窗口在曲终被收起。本次删除这些回调；已有进程（包含托盘进程）不属于六毛的
冷启动。Windows 命令使用客户端后台参数，只有本次启动前没有 QQ、实际播放
和模式已经确认、期间没有新用户输入时，才对匹配完整程序路径的主窗口收起一次。
任何新输入均放弃此次收起，之后的下一首、曲终和换轮不再隐藏窗口。
客户端自身仍可能决定是否展开窗口；本次没有修改 QQ 自身设置或自启动项。

Mac 已有 QQ 不重新启动、不激活、不调用 hide；尚未运行时使用 Cocoa 的
隐藏且不激活启动配置。仍须用户完成 QQ 登录与当前 Lili 的辅助功能授权。
设置里的 QQMusic.app 选择继续校验应用包标识和包内程序，并拒绝其他播放器、
残缺应用包或另一台电脑的无效路径。软件运行不依赖 Codex 或项目开发环境。

Mac AX 改为有时间、层数和节点限额的广度读取，批量读取公开属性，兼容搜索
子角色、占位文字、链接标签、播放按钮的快捷键描述及模式弹出按钮。搜索先使用
陈楚生及基础歌名，但结果必须核对完整版本歌名和全部所选歌手；没有 AXConfirm
时只能点击唯一的明确搜索按钮，不向其他应用发送回车或媒体键。模式按钮限定
已识别播放栏，不能读取或确认时停止并给出具体阶段。

设置新增异步“检查 QQ 适配”，读取本机 Lili／系统／QQ 版本、授权、唯一进程、
搜索框、搜索确认能力、播放栏和模式。它不启动 QQ、不播放、不改变模式、
不请求网络、不导出完整界面或账号文字；结果可选择复制，不自动上传。
检查期间关闭设置会请求取消，并等工作线程正常结束，不强制销毁运行中的线程。

Windows 媒体快照有时缺专辑。仅对明确的平台快照允许这一缺值，完整版本标题
和歌手仍须一致，非空但错误的专辑仍拒绝。QQ 的单次投递确认限额改为十秒，
没有重复发出播放请求，其他播放器默认仍为五秒。播放尚未确认时保留实际失败
阶段，不再用模式接管错误覆盖。随机目录排除明确试听、片段、预告，以及元数据
时长不足九十秒的条目；已保存的旧歌单需重新点击随机来更新。

Windows 生产管理器的全新配置实测：QQ 正常退出后，随机生成三十首并确认播放
《那个远方 + 奔赴星空 (Live)》，首次窗口收起成功；随后正常打开 QQ，随机首曲
《耍赖》、手动下一首及原生曲终接到《我真的受伤了》，主窗口均保持显示。
曲终测试在 QA 中定位到歌曲最后四秒后等待真实原生结束，并非完整自然播放验收；
定位命令不进入产品路径。每段测试有三十秒守卫，结束暂停；不重启正常六毛或专注计时。

Mac QQ 在线控制仍为实验适配，尚无带登录和授权的实机搜索、播放及连续换轮证据。
Mac 的完整回归、原生 SDK 绑定检查、冻结应用启动和双架构 DMG 构建分别验证，
不能替代 QQ 在线播放验收。两个 DMG 仍未 Developer ID 签名或公证。
