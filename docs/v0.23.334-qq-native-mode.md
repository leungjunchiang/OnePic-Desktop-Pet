# v0.23.334 QQ 已打开时的模式接管

v0.23.333 为避免 QQ 原队列插歌，要求先确认单曲循环。但本次 Windows 客户端没有
公开 GSMTC 重复模式能力；QQ 已打开、媒体会话存在，也不代表它的模式按钮能接收
后台 Invoke。旧链路还先最小化客户端，屏幕外的按钮会拒绝这类动作。

本次在已安装 QQMusic2276.10.06.08 的客户端命令入口发现 `/playmode`，通过暂停状态
下逐次投递和播放栏读回，验证 1 单曲循环、2 顺序播放、3 列表循环、4 随机播放。
产品仅向真实存在、完整路径匹配且已运行的 QQMusic.exe 传递这些固定数值，始终
使用参数数组且不启动 shell、不终止 QQ、不修改 QQ 配置文件或云端收藏。

原生命令只是投递；只有读回目标模式才确认接管。请求仍运行在现有的限时独立
辅助进程，不把 UIA/COM 带进 Qt 进程。客户端不接受命令或未公开明确模式时，
继续尝试标准可访问性动作；仍失败则暂停并说明如何在 QQ 播放栏设置，不伪报成功。
其他版本的数值行为必须以目标客户端实际读回为准。

QQ 原生命令会产生短暂窗口，旧的窗口枚举结果可能在 UIA 访问前已经失效。现在
跳过这些失效窗口和重建中的控件，继续寻找真实播放栏；没有有效播放栏或出现
互相冲突的模式仍失败。标准动作的 False 返回值与异常都会尝试备用动作。

模式准备安排在后台最小化之前。确认后沿用 v0.23.333 的完整曲终、同曲回绕、
歌单顺序和 30 首换轮机制；暂停恢复接管前的模式，保留用户后来主动选择的模式。
不移除单曲确认前提，也不回到原队列插歌后快速纠正的旧方案。

回归覆盖固定参数与运行路径、命令已接受但读回不变、取消、失效窗口、冲突模式、
动作布尔返回值和真实 OnlinePlayer/QQPlaylist 的隐藏时序。真实播放使用独立测试
配置与限时暂停保护，曲终验收记录最后十秒附近的媒体标题，检查是否有第三首。
冻结包检查独立辅助入口。Mac 继续使用原 AX 通道，在线点歌仍为试验适配；本次
Windows 原生命令不用于 Mac。无账号、专注历史、私有素材或云服务部署变更。
