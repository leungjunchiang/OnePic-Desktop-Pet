# v0.23.302 自习室、纪律记录与同步核查

## 根因与对应代码

| 问题 | 实际原因与修复 |
|---|---|
| 长期离线卡片空白 | `BuddyCardWidget` 的纵向尺寸策略和根据列表而非实际 viewport 估算高度，使换行后的布局高度与 item 分配不一致；最后确认、娃衣也被统一换行设置覆盖。`social_ui.py` 改为纵向 Maximum、AlignTop、内容行不伸展，`_set_buddy_item_height` 使用 viewport 宽度及 `totalHeightForWidth`，Resize 重新计算。真实 Qt 单张卡片约 141px，确认与娃衣间隔 3px；剩余空间留在列表外部。没有用小固定高度截断内容。 |
| 离线仍显示休息 | 过去直接沿用业务状态，已加载的旧状态没有统一经过 TTL。`_presence_status` 先检查真实心跳，再判断业务状态；profile 更新时间不能覆盖已过期心跳。卡片、详情、排序共同使用该函数。 |
| 实际开工不一致 | 报告以前使用专注时间轴的首段边界，跨午夜裁剪后可能是 00:00；纪律页又使用不同事件。`discipline.get_actual_work_start` 统一取本地当天 06:00 后首次真实 start_work，报告和记录共用，服务端摘要也过滤恢复事件并使用原始本地时钟。 |
| 重复纪律上传 | 旧 `lili_discipline_sync` 反复提交最多 2000 条历史事件并返回配置。新 `lili_discipline_sync_delta` 使用持久 ACK 指纹、账户游标、最多 100 条页；心跳不参与。告警/普通暂停恢复不进入云端账本。 |
| 多设备晚提交丢失 | 单纯时间游标难以处理离线设备补交与并发提交。事件 revision 在账户事务锁内递增，游标只随已合并响应持久化；晚到 ACK 不清除后来编辑的说明。较早真实开工修正规范开工与最终迟到。 |
| 低频配置被夹带读取 | 旧纪律运行时 RPC 每次返回完整设置与监督关系；现在 idle 响应仅包含轻量运行时状态、增量事件与有界提醒。完整设置仅进入页面、保存或手动刷新读取。 |
| 再次工作仍有旧缺口 | 同一天结算以前只追加一次。日/周缺口、提前下班及最终摘要随最后一次主动结束更新，补足目标或晚些下班后清除过期待说明；保留已填写说明和同一事件 ID。 |

## 产品边界

- **工作报告**：从本机原始专注段及缓存计算时长、有效段、连续段、深度时间、分布、节奏、趋势，不上传完整派生报告。
- **记录**：开工、计划、迟到、目标缺口、长休、待说明、免战与结算。今日四个紧凑指标；本周为纪律概览；历史按结算日期分组，选择日期可展开与填写说明。今日待说明也可直接处理。
- 今日 / 本周 / 历史等宽铺满，48px 高，选中青绿色与底部高亮；内容高度自然增长。
- 免战为标题旁状态，已挂时隐藏操作入口。当日免迟到、长休、催开工、缺口规则，周目标不减。
- 06:00 仅用于真实开工与纪律判定，本次没有把自然日专注统计整体改成 06:00 跨日。凌晨专注仍计入既有自然日时长。
- 首次开工在关闭训导时也保存事实；恢复、启动、重连、心跳、睡眠封存不生成开工。尚未开工时不按当前时间每分钟追加迟到。
- 普通短休、暂停、恢复、定时刷新不进入今日纪律事件；长休只在休息结束形成最终结果，预警仅本地去重。

## 请求与数据口径（实际代码）

| 项目 | 当前行为 |
|---|---|
| 心跳 | 独立 worker 每 15 秒；原子 RPC 参数仅 `p_working`, `p_session_active`, `p_session_id`, `p_session_started_at`, `p_device_id`, `p_sequence`, `p_input_idle_seconds`。账户来自认证，服务端写 `last_seen_at`。不带时长、计划、权限、报告、订阅、纪律历史。 |
| 在线 TTL | 120 秒。超过后 working / resting 都显示 offline；保留内部工作状态，断线不产生开工/下班事件。 |
| 高频计时 | 本地计时器，页面不为每秒累计值查询服务端。 |
| 原始事实 | 已封存的 FocusSession 区间 / `lili_focus_segments`；今日、本周由去重区间并集派生。兼容旧账户已核验的冻结基线，未删除旧累计字段。 |
| 本地安全 checkpoint | 每 60 秒持久化当前活动段。 |
| 云端 checkpoint | 长专注每 900 秒封存并同步；暂停、结束、睡眠、退出、账户切换、跨日等重要边界也封存并异步提交。 |
| 本人空闲增量刷新 | 5 分钟；有待封存事实、账户/娃衣变更等仍及时同步。兼容 profile 仅首次确认或娃衣变化时写，不随每次时长 delta 重写。 |
| 普通 pause / resume | 仍可能产生必要的最小状态请求、暂停时原始区间提交；没有假称完全零请求。不会产生普通切换纪律云端流水。 |
| 工作计划 | 进入计划/记录页面一次；实际修改保存一次；明确手动刷新一次。普通统计与心跳不读取配置。 |
| 训导权限 | 完整权限表单进入 / 手动刷新 / 保存读取；不轮询表单。运行时有效模式、enabled、revision、撤权租约和短期轻提醒仍每 60 秒轻量核验，离线授权最多保留既有 120 秒。 |
| 提醒订阅 | 初次、主动刷新或修改读取完整订阅；60 秒事件轮询只读取 `lili_buddy_reminder_events`，不反复下载完整订阅。提醒关闭不修改订阅。 |
| 纪律写入 | 首次实际开工、最终迟到、长休最终超时、主动下班、提前下班、日/周最终缺口、纪律结算摘要、免战，以及用户说明。以本地 outbox 批量最多 100 条、明确 ACK 后清除。 |
| 纪律 idle 同步 | 60 秒增量事件与必要运行时状态；待提交数据约 5 秒合并。没有未确认数据时不上传旧全量账本。 |
| 搭子首页冷读取 | 实际 HTTP 路径计数：1 位和 10 位搭子同为 4 次批量请求：dashboard、requests、private notes、reminder snapshot。第二次普通缓存刷新 0 新请求。 |
| 首页缓存 | dashboard 90 秒、请求/备注 300 秒；可选 live projection 60 秒账户缓存，缺少接口暂退 300 秒。提醒 60 秒。手动强制刷新可绕缓存。 |
| 其他请求边界 | 上述 4 次只指首页冷加载，不是整个程序全局计数。独立后台在线投影、提醒、运行时及进入选中房间的 2 次房间读取另计。每卡片不请求计划/纪律/报告/全量 sessions，没有逐搭子 N×N 查询。 |
| 报告上传 | 不上传专注分析报告。云端 `daily_report` 是少量纪律结算字段，服务于授权后的纪律查看；不是第二份完整工作报告。 |

## 持久性、数据库和旧数据

`DisciplineStore` 保存 schema 2、ACK 指纹、已同步配置时间及账户游标。响应先合并再确认；请求失败或行校验失败不确认。相同事件幂等提交，迟到的旧 ACK 不清除新说明；本地草稿与远端配置版本仍合并保护。工作计划保存也修复了覆盖训导草稿的问题。

数据库扩展已有幂等部署 bundle `supabase/migrations/20260930180000_lili_study_plan_semantics.sql`：事件 revision 列/序列/索引/事务锁触发器、增量 RPC、轻量运行时 RPC、提醒事件专用 RPC、统一实际开工函数。现有 Release 脚本原子重放部署，保留旧 RPC 供旧客户端兼容；没有创建重复统计表，没有修改原始专注事实。旧重复过程事件保留在库中，但新版纪律展示/同步过滤。

所有私有 RPC 验证 auth.uid；权限摘要继续逐字段过滤，内部函数不可由客户端执行，未扩大 authenticated 直接读事件表权限。`scripts/verify_discipline_delta.sql` 用合成账户执行真实 RPC 与 rollback：ACK、重放、分页、另一账户隔离、无认证拒绝、权限、较早设备修正、恢复事件排除、最终摘要与缺口更正、原始事实不变。

异常退出后沿用 `WorkTimer` 已持久化 checkpoint 和待封存队列修复未闭合区间；只封存最后安全点，不自动把离线小时数计作工作。正常 checkpoint 调度下活动尾部风险约 60 秒，突然断电/事件循环长期阻塞不承诺零丢失。离线队列在恢复网络后重试，明确 ACK 才移除。

## 验证与边界

- 新增 17 项关键测试：真实开工、显式时区、02:00 旧记录兼容、无开工迟到不入账、普通暂停本地化、持久 ACK、晚 ACK、远端说明保护、双设备较早开工修正、TTL 边界、真实单卡高度、缓存请求次数、分页及共享报告口径、三级导航/历史说明、再次工作结算更正。
- 本机执行完整既有测试（Qt 模块分进程、window 分组）、编译、隔离演示启动及真实 Qt 页面渲染。发布必须通过真实数据库核验和 Windows / macOS 两架构测试、打包门禁。
- 本机仅直接验证 Windows Qt 渲染；macOS 由对应 CI runner 测试与构建，不声称真人三平台交互测试。
- 后台新事件可能有约 60 秒同步延迟，空闲原始事实补读最长约 5 分钟。旧客户端直到升级仍使用旧全量纪律接口，无法由新版单方面消除其带宽。
- 原始自然日统计、服务端免战与旧事件日期仍沿用既有中国时区日历；实际开工使用记录的本地时钟。跨时区旅行或设备各自设置不同工作日历属于现有边界，没有在本次强行重写整个日历体系。
- 本地 06:00 前已开始且连续跨过 06:00，不视作 06:00 后新开工；需下一次真实进入专注，符合首次真实转换定义。
- macOS 安装包继续 unsigned。既有不抢焦点提醒、订阅持久性、投喂菜单与 hover/pressed 反馈保留。
