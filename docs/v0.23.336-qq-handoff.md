# v0.23.336 曲终衔接

v0.23.335 用真实单曲循环隔离 QQ 原队列，并等待进度回绕后再投递下一首。
它解决了插播第三首，但每秒检测加上投递期间的重复播放，会让上一首重唱开头。
旧的自然曲终验收只检查了歌单顺序与第三首，遗漏了这个衔接体验。

Windows GSMTC 除原始进度外，现在提供经验证的快照年龄：Playing、正常速率、
LastUpdatedTime 不在未来且距当前不超过两秒。只有原始曲末 2.5 秒范围内至少
两次实际推进、同一歌曲与时长、推算完整截止时间已过，才允许不等回绕直接交接。
多个预测取较晚截止时间，不使用固定提前量。中途外推到末尾、单次快照、陈旧
更新时间、缓冲后刷新、回拉和暂停不能走这条快路径。

检测平时仍为一秒，曲末短时改为 75ms；超过预计结束两秒仍停滞则恢复普通频率。
完整曲终后先暂停经过唯一会话核对的 QQ，不释放单曲隔离模式，确认暂停后立即
按保存的列表投递下一首。暂停失败会停止续播，不发全局媒体键或误控其他应用。
用户的主动暂停仍优先取消在途操作并按原逻辑恢复原模式。

自动换轮复用已经获取的候选目录与公开元数据重新随机 30 首，不把在线目录查询
放在第 30 首曲终之后；用户再次点击随机仍会更新目录。音频仍由已登录的 QQ
在线播放，不下载歌曲、不访问账号凭据、不修改 QQ 云歌单。

客户端缺少新鲜时间轴时仍走真实回绕或稳定结束的保守判断。Mac 当前没有这项
GSMTC 时间戳，沿用实验性 AX 通道及保守判据；本版不能据此承诺 Mac 无缝衔接。
跨进程点歌仍可能有 QQ 自身的装载间隔，这不是客户端原生的 gapless 播放队列。

测试覆盖可靠曲末、尚未到期、原始进度仍在中途、时间戳异常、缓冲、暂停、回拉、
短时加密轮询、唯一 QQ 的暂停交接及免联网换轮。自然曲终与换轮真实观察及三平台
安装包验证结果在最终 Release 说明中记录，模拟回归不等于另一台电脑的实测。
