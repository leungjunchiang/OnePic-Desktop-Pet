# v0.23.336 · QQ 原生临时队列

Windows 随机入口仍先保存 30 首本机歌单，再把完整歌曲资料交给 QQ 的临时队列。
QQ 使用读回确认的顺序播放，自行处理普通曲终；六毛只跟随当前曲目更新序号和
保存位置，不在每首曲终发送暂停或重发下一首。这样避免单曲循环先重唱开头，
也避免原队列插入歌曲后由六毛快速纠正。

每次点击随机重新选取 30 首。列表中的上一首、下一首和选曲会投递同一列表及
选中位置。到第 30 首后等待稳定的结束证据，再将已经取得资料的 30 首重新洗牌
成下一轮，不在曲终发起目录请求。暂停会取消在途操作，恢复用户原播放模式；
重启只恢复本机列表，首次继续前重新投递临时队列。
手动切歌、暂停和恢复先同步 QQ 实际位置，覆盖曲终已切换而六毛一秒轮询尚未到的间隙。

## 协议边界

只调用已安装 QQMusic.exe 的原生命令，不注册 COM、不加载实验 SDK，不下载音频。
完整公开元数据按 10 首分批只读取得，核对数字 ID、歌手、完整版本标题、专辑及
文件资料。QQ 详情的 name 可能不含 Live，title 才包含版本标记，校验使用后者。
QQ 处理授权、会员限制、网络和实际播放，命令返回不能代替媒体状态确认。

临时命令为 playSong，depot=0、justPlay=0，明确不含 listId 和 listName。
此前诊断发现 listId 即使为 -1 也会转入自建歌单路径，所以正式实现禁止发送该
字段。实验曾产生额外测试歌单；不将这些诊断命令、日志、依赖或 32 位运行时
放入安装包，也不直接修改 QQ 数据库。应用只创建自己的延迟清理临时文件。

模式识别兼容首页“上一曲／下一曲”和详情页“上一首／下一首”，要求同一播放栏，
拒绝冲突模式；广度优先遍历避免网页分支耗尽查询预算。模式失败提示 Windows
所需的顺序播放，不再要求这一路径切成单曲循环。

## 验证门槛与平台限制

旧的时间轴加密和单曲回绕方案在完整自然曲终观察到约 190ms 旧曲开头，未通过
体验验收，现已由 Windows 原生队列路径替换。Stopped 也可能仍有尾音，普通
换曲完全交给 QQ；换轮保留完整截止时间和稳定结束观察，不根据一次停止抢切。

回归覆盖完整队列次序、选中位置、禁止云歌单字段、错误元数据、Live 标记、取消、
缓存、原生换曲只更新位置、暂停恢复、外部队列拒绝及免联网换轮。发布还要求
完整自然曲终无旧曲开头/无第三首、第 30 首换轮及最终暂停的真实观察；具体记录
以 Release 说明为准，构建和模拟回归不能代替在线播放验收。

Mac 沿用已授权 AX 的试验适配及保守曲终判断，不使用 Windows 原生命令。
Apple Silicon/Intel DMG 都需独立测试与冻结启动门禁；未有 Mac 真机 QQ 在线
播放验收，不能据 Windows 结果承诺 Mac 同样衔接。DMG 未经 Developer ID 签名
或公证。另一台电脑未远程验收，歌单按设备保存在本机。
