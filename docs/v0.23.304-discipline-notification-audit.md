# v0.23.304 训导通知核查

## 创建组件与真实路径

项目使用 PySide6 / Qt，没有 Tk Toplevel。桌面窗口由 `window.PetWindow._show_discipline_notice` 构造 `buddy_reminder_toast.BuddyReminderToast`：Tool、无边框、置顶、不接受焦点，原先允许四个窗口叠放。它原用于本机计划提醒和搭子提醒两类场景。

代码中存在两个启动补发路径：

1. `_discipline_sync_completed` 初次拉取最近三分钟的 `nudges`，只有 seen_nudges 判重，没有 initial hydrate 基线；另一台电脑或本地没有读过的旧 ID 会被当新消息。
2. `_discipline_tick` 调用 `evaluate` 和 `break_notices`。严格模式晚于计划启动时，单轮可同时命中三个未开工阈值；恢复旧休息段时也可能补发多个阈值。三个阈值同时创建三个窗口已由回归复现，不需要初始化函数执行三遍。

每条都走构造窗口，无统一单实例合并；12 秒后隐藏正文并将标题截断，迷你状态易只剩「训导主任：」开头。主窗口 closeEvent 还未关闭这些无父窗口 Toast，原来只有账号切换清理列表。这些路径可以确认；用户本次未附实际截图/日志，无法逐一证明现场三条具体来自哪个 ID 或阈值。

真实 Windows Qt 预览另外确认了透明 QFrame 的样式背景未绘制，截图底板像素 alpha=0，因此可透出后方桌面图标。改为 paintEvent 显式绘制深色圆角底板，像素验证 alpha=255；迷你数量标题按字体宽度调整并单行省略，避免再换行挤成标题残片。

## 通知判定与数据兼容

- 第一份成功、明确的 nudges 列表（包括空列表）建立本次账号基线；错误、离线缓存和缺少 inbox 的结果不建立基线。
- hydrate 到的所有旧事项静默保存；后续页面刷新、心跳、重连及迟到旧页不能凭新 ID 重放旧时间。
- 同账号重新认证保留运行基线、去重和已有通知，重连后的真正新消息正常到达；退出登录或实际切换账号才清空基线。
- ID 先记为 seen 再决定展示，因此勿扰、免战或空内容不会在条件解除后补弹。
- 缺失/无时区/无效/未来 created_at 不能证明是即时新事件，静默留存，不制造通知。
- 实时多条合成「训导主任 · N 条新事项」；同一窗口更新，完整展示最近三条摘要，其余在今日查看。关闭后未来另一件新事可再弹，旧 ID 不再弹。
- 现有待说明、迟到、欠账和补时纪律事件保持不变，未创建第二套纪律事件。原始历史记录不清空，旧配置 JSON 缺字段正常加载。
- 无新增数据库结构、migration、RPC 或请求频率；沿用服务端最近三分钟 nudge 窗口，未处理纪律仍从原账本读取。较早未保存到本地且超过服务端窗口的普通提醒无法恢复全部正文，本版不声称补出不存在的历史。
- 基线采用本机时间比较服务端时间；机器时钟严重不准时优先静默，避免启动补弹。跨设备各自建立运行基线，未增加全账号互斥通知锁。

## 不抢焦点与退出

Qt 的 WindowDoesNotAcceptFocus、WA_ShowWithoutActivating 和 NoFocus 保留；Windows 继续使用 WS_EX_NOACTIVATE、SW_SHOWNOACTIVATE、SWP_NOACTIVATE。收到消息或合并不会打开主窗口、Focus 或 Activate；只有用户点击才跳转专注今日。右键/×只关闭当前通知。

本机额外使用真实 Windows Qt 平台调用 GetForegroundWindow 比较显示、mini、合并更新和关闭四个阶段，前台 HWND 全程未变化；并检查实际组件截图。该验证不代表已在用户的 Word 或游戏输入场景逐一测试。

所有 Toast 都归属 PetWindow；dismissed 清除列表并排队销毁。closeEvent 一开始停止纪律 tick 和合并 timer，关闭所有提醒；即使网络线程还在退出，也不能重新创建提醒。保留原线程安全退出流程，不同步阻塞 GUI 等待网络。
