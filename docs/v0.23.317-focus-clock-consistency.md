# v0.23.317：长时间计时、午夜与搭子统计审计

## 已确认的代码缺陷

| 位置 | 旧行为 | 修复 |
| --- | --- | --- |
| `WorkTimerModel.checkpoint` | 每分钟取整 elapsed，再把 monotonic 起点直接设为 now；每次不足一秒的部分丢失，长时间累积 | 起点只推进已入账的整秒，保留尾数；可信墙钟 checkpoint 同步对齐，崩溃恢复仍只恢复已保存整数前缀 |
| `PetWindow._shared_focus_period_seconds` | canonical 缓存以 current_elapsed_seconds 推进；磁盘保存会归零该值，却不失效缓存 | 使用持续增长的逻辑 session_seconds 作为增量锚点，缓存仍按账号、日期、会话、事实修订失效 |
| `SocialHubDialog.apply_dashboard` / `_decorate_leaderboard_rows` | 卡片取得新 dashboard，榜单仍使用另一份旧响应，缺少榜单字段时不更新 | 按 user_id 将已参与榜单的搭子映射到同一 canonical 周总量；收到延迟 RPC 也使用当前卡片投影，不新增参榜成员 |
| `SocialClient.focus_leaderboard` | 五分钟缓存只含账号与 period，可能跨周沿用 | 缓存增加北京周起点；UI 拒绝显式标记为旧周的榜单行 |

不是用 `max(旧值, 新值)` 掩盖问题：当前可靠 dashboard 的更低修正也会更新榜单。隐藏/null、旧本地缓存、非 canonical 来源不会作为新统计覆盖榜单。昵称只用于展示，不作为账号关联键。

## 服务端证据与时间语义

2026-10-03 的定向只读汇总检查：对方活跃账号的 10 月 2 日有效专注仍为 **23,885 秒（6小时38分05秒）**，不是两分钟；本人账号为 **35,869 秒（9小时57分49秒）**。同名历史账号没有当周记录，因此没有按昵称混合数据。公开说明不包含账号 ID。

部署中的 `lili_focus_weekly_leaderboard` 使用 `lili_effective_focus_week_seconds`，该函数读取 `lili_effective_focus_stats.week_seconds`；有效日统计复用北京时间窗口裁剪的 interval union 和既有 legacy ledger。没有发现这两处服务器函数分别按 UTC/北京时间计周的证据。

午夜后“今日两分钟/六分钟”可能是新一天正常结果。昨日六小时多仍属于昨日，也仍在同一周的累计中；不能将昨日时长搬到今日来修复。截图缺少准确采集时刻，用户尚未提供现场 Mac 运行日志，不能断言截图中的每一分钟变化或旧榜单数值产生的全部路径。

## 同步与历史数据

- 不改数据库结构，不修改真实用户历史区间，不推算补写缺失的秒数。
- 心跳继续 15 秒、在线 TTL 120 秒，网络与配置轮询保持原频率。
- 本地保存仍至少 60 秒；可同步的长会话原始片段仍按 15 分钟、暂停、结束、退出、北京时间午夜边界封存，原有 durable outbox 与恢复策略保持。
- 榜单仍至多五分钟一次；新 dashboard 更新榜单时仅组装本地数据，不增加 Supabase 查询或 N+1 请求。
- 既有整数 checkpoint 继续兼容；已丢掉的亚秒尾数没有事实来源，不能伪造历史恢复。

## 验证

- 600 次带 0.75 秒延迟的 checkpoint，累计 36,450 秒不丢失；恢复保存前缀、有效截止时间、暂停校验。
  用 v0.23.316 原实现运行同一时钟：记录 36,000 秒，损失 450 秒；修复后记录 36,450 秒，损失为零。这是合成延迟复现，不表示现场恰好损失 450 秒。
- 同一缓存跨多次磁盘 checkpoint 持续推进；23:52 到 00:02：今日 120 秒，本周保留 600 秒，不额外扫描数据。
- 复现榜单 32h51m、卡片 39h35m 后本地一致；同名不同 ID 隔离、延迟 RPC、真实减值修正、隐藏值兼容。
- 五分钟缓存跨北京周一立即隔离，周内继续复用。
- `scripts/verify_focus_clock_consistency.sql` 在真实 Postgres 用随机合成账号验证重叠去重、跨日裁剪、昨日保留、共享周统计、不同服务器时区；全部 rollback，不使用真实账号身份。
- 完整 Python 与三平台打包测试通过后发布；现场 Mac 睡眠/网络/手动暂停组合仍需日志精确核对，不将本机 Windows 离屏测试宣称为现场重现。
- 全套测试发现旧免战按钮反馈测试隐含“今天是工作日”，周六执行会提前进入正常的固定休息日分支；测试现明确设置七天工作计划，生产免战规则不改变。
- 本地完整测试：1,352 项通过；`compileall` 与 `git diff --check` 通过。真实 SQL 合成事实验证已通过并回滚，发布 CI 会再次执行。
- 首轮 Mac ARM CI 的既有退出测试使用固定 300ms 等待，和生产 250ms 重试及其他 Qt worker 清理发生竞争；改为最多两秒的事件循环条件等待，仍要求离线 ACK、主线程不阻塞、最终隐藏及只有一次 offline。生产退出机制未改。

时间口径遵循 [Supabase 数据库时区说明](https://supabase.com/docs/guides/database/postgres/configuration)：存储 UTC 时间点，业务显示/裁剪转换到 Asia/Shanghai，持续时长不手工加减八小时。
