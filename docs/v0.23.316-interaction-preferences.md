# v0.23.316：搭子互动默认开启与误关闭防护

## 原因

服务器的直接互动 RPC 会检查接收者 `allow_visits` 和 `buddy_interaction_mode`。任意一个明确关闭，都会返回截图中的“对方暂时不接受搭子互动”。单靠发送方无法从该错误判断接收者何时、为何关闭。

客户端确实存在可导致误关闭的路径：`SocialHubDialog._save_profile()` 保存任意资料时，无条件提交当前电脑的 `allow_visits`，并调用模式 RPC；另一电脑的旧值因此可能覆盖最新选择。此外，checkbox 构造时没有默认勾选，授权尚未加载也可能提交 False；`apply_dashboard()` 刷新无条件重设控件，丢失未保存的编辑。

## 修改

- `_profile_card()` 默认勾选接收搭子互动、默认 welcome；明确区分专注优先（仍接收）和手动暂停接收。暂停时提供“恢复欢迎互动”。
- `_render_interaction_preferences()` 按字段读取，缺字段不当 False，blockSignals 防止服务端赋值误标成用户编辑，dirty 字段保留。
- `_save_profile()` 只提交主动修改的互动字段；先成功的接收字段单独确认，模式失败仍可重试。保存按钮与光标在 finally 恢复。
- HTTP direct、relay/proxy、legacy 资料 PATCH 都支持省略 `allow_visits`；显式 False 保持有效。未修改模式就不调用模式 RPC。
- 账号切换清空编辑/待确认状态；刚保存的值有最多 15 秒本地保护，防止在途旧快照回滚，保护过期后接收远端明确变化。
- `supabase/direct_interactions.sql` 复用已有原子升级入口，把新账号列默认设为 allow_visits=true / mode=welcome；无新增表、字段、RPC，不 UPDATE 既有账号偏好。

## 数据与通知边界

心跳、Presence、FocusSession、后台 quiet mode 和全屏隐藏均不修改接收权限。全屏/游戏仍沿用不抢焦点与被动提示 suppression。服务器可以保存互动，而本地不必弹窗。

不新增任何轮询或读取。保存普通资料少调用一次无必要的模式 RPC。

不能让发送方强行开启另一个人的设置。旧账号手动关闭过接收或选择过免打扰，可主动使用“恢复欢迎互动”；两台电脑建议都更新，旧版客户端仍可能提交整个资料对象。本轮没有服务器 CAS 版本协议，两个设备主动同时修改同一设置仍以最后成功写入为准。

## 验证

`test_interaction_preferences.py` 覆盖默认欢迎、缺字段、旧设备保存主人名、刷新保留编辑、明确关闭仅提交一次、单字段写入、失败重试、账号切换、恢复两个开关，以及 direct/proxy/legacy 传输省略字段（11 项）。既有 social / social_ui 回归通过。

发布部署调用真实 PostgreSQL 回滚验证：新注册的合成账号默认接收 welcome；重放升级不覆盖已明确关闭的合成账号；直接回应的原发送者鉴权、去重、非搭子拒绝和免打扰拒绝仍有效。合成测试全部 rollback。

本轮 Supabase Security Advisors 读取成功：存在既有 authenticated SECURITY DEFINER RPC 提示及 RPC 专用表无直接策略提示；本轮不改变这些权限，保留空 search_path、auth.uid 及匿名拒绝。另有既有泄露密码保护未开启提示，本轮不更改 Auth 设置。[RPC 提示说明](https://supabase.com/docs/guides/database/database-linter?lint=0029_authenticated_security_definer_function_executable)、[RPC 专用表 RLS 提示](https://supabase.com/docs/guides/database/database-linter?lint=0008_rls_enabled_no_policy)、[密码保护说明](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection)。
