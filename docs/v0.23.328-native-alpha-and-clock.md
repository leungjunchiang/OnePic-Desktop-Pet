# v0.23.328 · 原生透明通道与实时计时卡顿

## 本次证据

用户确认升级后仍看到黑色外圈和卡顿。runtime.log 的 2026-10-08 14:07 更新检查确认当前版本为 0.23.327。随后日志仍有 100–200ms 的定期 GUI lag；focus.maintenance 的一次摘要平均约 120ms、最高约 294ms。

只读检查正在运行的真实 PetWindow HWND：非客户区渲染已经关闭、class style 没有 CS_DROPSHADOW，但 extended style=0x08000088，缺少逐像素透明所需的 WS_EX_LAYERED。上一版只检验了独立测试窗口的阴影属性，没有重放恢复账号时提前创建 native handle 的场景。

PetWindow 原来在 _switch_focus_account 等初始化之后才设置 WA_TranslucentBackground。native handle 如果已经存在，后设属性不能保证 Qt 已创建的 backing store 获得 alpha 通道。现在在 self.settings 赋值后立即配置透明、无框和非激活属性，再初始化业务；回归特意在账号恢复入口请求 winId，验证 alphaBufferSize >= 8。Windows 原生测试还检查 show 与置顶切换之后保留 WS_EX_LAYERED、foreground 不变。

原生桥只为明确配置 WA_TranslucentBackground 的窗口保留 WS_EX_LAYERED；显式按 HWND 设置 DWMNCRP_DISABLED（成功后不每三秒重复设置），继续保留 NOACTIVATE。普通不透明报告/对话框不加 layered。诊断补充 qt_translucent/native_layered/shadow_policy_applied。这里修复的是透明和原生阴影路径，不删除角色画稿本身的正常黑色描边；用户桌面的视觉效果仍需升级后验收。

## 卡顿路径

_cross_device_today_display_value 每个实时 tick 都解析远端记录和所有本机历史。哪怕 fresh live rows 是空列表，仍会走全量分支；维护回调也会调用这条路径。原来的 0.75 秒标量缓存不能避免下一秒再次扫描。

新增 prepare_today_display_rows：完整历史先验证，再留下与北京时间当天相交的不可变区间。缓存按账号、北京时间日期、事实 revision 和远端快照更新失效。每秒仍调用原有区间并集函数，只处理当天历史、当前本机片段和少量远端在线片段。没有新增另一套时长公式。远端 live TTL、暂停冻结、跨午夜、未来 end 的每刻裁剪都继续使用原有规则；外账号或无效旧记录不会因为日期过滤而被忽略。

使用现有账本的内存副本、persist=False 只读重放：五次热 tick 平均从 92.531ms 降至 1.054ms，历史读取从六次降至一次，五次累计值逐项相等，输入状态逐项相等。此数值属于本机重放，不代表所有电脑的固定帧率。

## 验证和数据边界

- Windows 原生 alpha 提前创建、置顶重建、无系统阴影及 foreground 保持测试通过。
- 完整历史缓存的跨日区间、未来 end、跨设备重叠、TTL 到期和 revision 失效回归。
- 原有专注时钟、透明遮罩、被动通知、今日累计常驻和原生窗口策略回归。
- 完整测试和发布打包继续作为 Release 的门槛。

没有数据库或服务端协议变更，没有新增网络查询，没有写回用户账本，没有使用重置卡。画稿、历史和闹钟设置均保留。

透明属性需要在原生窗口创建前配置，见 [Qt QWidget 透明窗口说明](https://doc.qt.io/qt-6/qwidget.html#creating-translucent-windows)；DWM 策略接口见 [Microsoft DWMNCRENDERINGPOLICY](https://learn.microsoft.com/en-us/windows/win32/api/dwmapi/ne-dwmapi-dwmncrenderingpolicy)。
