# v0.23.333 QQ 队列隔离与歌单定位

v0.23.332 的自然曲终验收只核对了“完整时长后发下一首”，没有把期间所有媒体标题
纳入通过条件。QQ 自己的随机队列会先开始另一首，六毛才投递自己歌单的下一首。
延长结束确认不能消除这段插播。本版把队列隔离作为连续播放的前提。

歌单开始后读取 QQ 播放栏的真实模式，尝试通过目标客户端的可访问性动作切到
“单曲循环”，并再次读取确认。Windows 只选择完整路径匹配的 QQ 窗口、相邻有
上一曲/下一曲的模式按钮；不发送全局按键、不点击猜测坐标、不改 QQ 云歌单。
macOS 通过已授权 AX 按钮尝试同样逻辑，仍为试验适配。

确认单曲模式后，QQ 不再从原队列挑选另一首；六毛观察同一首的真实曲末到开头的
回绕，再发送六毛歌单下一首。仍要求完整时长截止时间已到，提前拖回进度不续播。
已知的模式被客户端拒绝或无法明确确认时，暂停并提示先把 QQ 设为单曲循环，
不再把原队列插播后的“快速纠正”当作成功。用户本来就是单曲循环时不改模式；
普通暂停尝试恢复本次接管前的模式，用户后来主动改模式时不覆盖其选择。

本机客户端可读到随机播放，但标准后台 Invoke/默认可访问性动作被拒绝，因此需要
用户先选择单曲循环才能进行最终无插播实测。模式读回失败不会显示连续播放成功。
其他客户端版本是否接受后台切换需要以实际读回为准，不能只凭按钮存在确认。

实机还发现直接在 Qt 进程读取 UIA 会出现原生指针错误；Windows 模式访问现通过
先于 Qt 启动的独立辅助入口执行。每次请求均新建 COM 进程并限时，取消会结束本次
自有辅助，不复用跨线程 COM 指针。结果只回传到当前用户随机临时目录，冻结版另
验证辅助入口及类型库就绪，不启动桌宠、账号或音频。

点击随机入口时，未填写 QQ 程序地址会打开既有设置并滚动、聚焦到 QQ 地址框。
保存地址后继续同一次点歌；取消则不播放。歌单窗口“换一轮”同样经过此入口。
已填写地址仍直接复用后台音乐线程，不另开播放器或弹歌单。

手动查看歌单时，窗口放在六毛与快捷坞上方并随六毛移动、快捷坞高度和歌单尺寸
调整。使用实际窗口边框尺寸作屏幕约束；顶部不足时优先侧放，不覆盖宠物与按钮。
歌单仍能独立最小化和关闭，关闭不暂停。

回归覆盖模式读回、拒绝时暂停、原模式恢复、用户模式选择优先、完整回绕、30 次
回绕后换轮、地址取消/保存续播、设置滚动聚焦及上方定位/顶部边界。最终实机验收
必须同时记录整个曲终附近的媒体标题，确认中间没有第三首，成功或超时后立即暂停。
Windows / Apple Silicon / Intel 分别回归、打包和冻结启动检查；Mac QQ 在线控制
没有登录真机验收，DMG 仍未使用 Developer ID 签名/公证。无云服务部署或用户数据迁移。
