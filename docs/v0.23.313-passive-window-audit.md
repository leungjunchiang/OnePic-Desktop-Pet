# v0.23.313 · 游戏时的被动窗口与焦点审计

## 结论及证据边界

项目使用 PySide6/Qt，没有 Tk `Toplevel`。仅凭“几个小窗口闪过”的描述，无法确定用户当时收到的具体 event_id 或窗口；没有把候选来源写成现场结论。本次修复了可重现的代码缺口：

- `VisitStatusBubble._set_content()` 在嘲讽倒计时/串门状态刷新时直接 `show()`，绕过 PetWindow 全屏门禁。一次刷新还会更新其他独立附属层，因此多个窗口能够在同一轮被显示。
- `PetWindow._show_nonactivating()` 原先 Windows 顺序为 show → native policy，存在“显示后才补 WS_EX_NOACTIVATE”的空档；普通 speech 还先显示后定位。
- 隐藏气泡的旧 position helper 会因 `isVisible=false` 跳过首次定位。新增 prepare 模式，在第一次 show 前完成最终位置，避免先在桌面原点闪出。
- `IdleRecoveryDialog.show_hint()` 直接 show；快捷按钮 hover 和视觉特效有额外 raise；下载进度 `QProgressDialog` 有内部自动 show 路径。它们已统一被动显示或移除 raise。
- NotificationManager 原本已限单个 Toast，但普通互动另用独立 speech 窗口，持续状态气泡又绕开它。现在普通互动直接画进六毛原有像素，连新的 QWidget/原生子窗口都不创建。
- 部分接收路径在游戏/勿扰时提前 return，未消费展示资格；结束游戏后可能再次播放。现在仍消费 ID，历史/未读独立保留。
- 启动基线只能拦启动之前的记录，不能拦断线后积压的旧记录。新增 120 秒新鲜度，与现有 90 秒 dashboard 缓存兼容。

真实 DirectX 独占游戏未在本机实测；原生验证使用自有非激活窗口的真实 Win32 几何，监测实际桌面前台句柄。边框无关的全屏判定、普通最大化、跨屏/DPI 沿用 v0.23.311 的 16 项回归。不是把 Qt 全屏验收描述为某款游戏现场测试。

## 全项目静态清单

`python scripts/audit_passive_windows.py` 输出完整函数/文件/行号清单到 [window-sources.json](v0.23.313-window-sources.json)。统计口径是**源码入口**，不是同时运行的窗口数量，类声明和其 flags 设置可能描述同一个窗口：

- 149 个 Qt 窗口/对话框/菜单相关入口：24 个对话框类声明、32 个窗口 flags 设置、2 个带 flags 的父构造、91 个显式对话框/菜单调用。
- 64 个显式 focus/raise/exec 调用已列出；主要属于用户点击后的编辑页、菜单和必要确认。
- 额外 1 个嵌入 C#/PowerShell 的网易云播放适配器包含 `SetForegroundWindow`、`AttachThreadInput` 和 ShowWindow。它仅由用户点音乐快捷入口调用，不能声称全项目没有 SetForegroundWindow；普通通知不调用该适配器。PowerShell 进程使用 CREATE_NO_WINDOW。
- 没有 Toplevel、focus_force、focus_set、grab_set 或 grab_set_global。

## 统一规则与调度

1. 经理接收时和350ms合并完成时检查实时前台/游戏/勿扰；不是等750ms防抖刷新后才检查。Toast show自身再检查 owner，后一次拦截立即释放隐藏对象。
2. 主宠隐藏仍每750ms采样、两次相同才切换；真实全屏必须覆盖完整 monitor rect（4px误差），普通最大化工作区不算。前台所在屏与六毛 HWND monitor 比较。
3. 不许可先 return，不创建 Toast；全屏期间收到的事件照常保留历史和未读，消费展示ID；退出全屏不回放。
4. 基线首次成功批次静默，120秒以上积压不展示。同一运行周期稳定 ID 最多一次；页面刷新、同账号重连保持去重，换账号才重建。
5. 普通互动只绘制本体或显示在已打开自习室内部；即时正式摘要/邀请和开工/下班提醒共用经理，最多1个独立 Toast。
6. QObject经理对 worker 的 notify/observe/flush 通过 QueuedConnection 回所属GUI线程；网络 worker 不构造/销毁窗口。
7. topmost watchdog 只 reassert 六毛本体。附属窗仅在显示/生命周期节点校验样式；不通过 raise 或 SetForegroundWindow恢复通知。
8. 正常 scheduler 并非“同一事件注册了三条同类计时器”；存在一次 social coordinator、一次本地纪律规则定时器、一次本地闹钟单次 timer 和一次 heartbeat worker。原纪律规则 timer 60秒还独立拉远端，已移到现有15秒social协调入口；本地规则 timer 不再轮询服务器。
9. 现有 dashboard 缓存90秒、reaction低频60秒、coaching delta/inflight/60秒节流仍复用。重要用户操作可即时提交。有不同RPC的数据职责，**没有声称已合成一个服务端endpoint**；未新增按类型分别轮询、数据库结构或远端 suppression 状态。
10. 单实例锁沿用已有进程级 guard；正常退出清除经理timer/current、旧兼容通知和附属层。
11. 全屏/游戏的自动UI抑制不静音闹钟音频。会议/录屏与深度场景仍保留原有勿扰设置。用户回闹钟中心才显示完整控制，不自动抢回前台。

## 本地日志

沿用 `%LOCALAPPDATA%/Lili/diagnostics/lifecycle.log` 有界JSONL（1MiB×4）。记录北京时间毫秒、线程ID/名字、event_id、实际事件类型、creator、window_id、尺寸、noactivate、duplicate/expired/fullscreen等抑制原因及销毁。没有消息正文、凭据；不上传日志、不写 toast显示状态到Supabase。

例如 `notification.received`（event_type=cheer）→ `notification.inline`，或者 `notification.suppressed`。仅真的显示独立通知才有 `notification.create`，关闭有 `notification.destroy`。`passive-window.show/suppressed` 能识别持续附属层。

## 验证

- 完整本机回归：**1317 passed**（Windows，逐文件独立进程，窗口用例每40个一组）。新增20项针对性回归；后续将普通串门也移到4秒本体绘制并补充首次show前定位验收。
- Qt/Win32原生验收：225次前台采样保持不变；普通、最大化、无边框全屏/Qt全屏；全屏通知零新增Show；WS_EX_NOACTIVATE实际样式通过；最多1个Toast；普通互动没有新增控件；闹钟音频入口执行但隐藏卡无native HWND；退出无旧提示。
- [原生结果](v0.23.313-native-verification.json)；脚本 `scripts/verify_passive_windows.py` 可重跑，仅用自有非激活窗口。
- 本机真实 DirectX独占游戏、macOS原生焦点现场待用户环境确认，不能用单测冒充。公开 Windows/macOS构建还需发布流水线通过。
- 项目没有独立lint配置；使用 compileall、git diff --check、现有完整测试和打包门禁。
